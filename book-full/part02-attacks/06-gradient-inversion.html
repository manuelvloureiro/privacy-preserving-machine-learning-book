14  Gradient inversion

A phone keyboard learns from what its users type, but the raw text never leaves the phones. A server sends the current model \(\theta\) to each phone, the phone computes the gradient of the loss on its own few examples, and only that gradient goes back. The server averages the gradients of many phones and takes a gradient step on the model. This is the setting of federated learning (FL), and it is often described as private because “the data stay on the device”. This chapter asks one question about it: what does a single client’s gradient reveal about the client’s data?

The answer is often everything, and one idea explains why. In a fully connected layer, each row of the weight gradient is the layer’s input multiplied by a single number, the rate at which the loss changes with that row’s output. The bias gradient is the list of those numbers, one per row. So with one example, dividing a row of the weight gradient by the matching entry of the bias gradient gives back the input exactly. The chapter takes four steps. First, one division recovers the input of one example. Second, the signs of the last layer’s gradient give its label, because the true class is the only one whose entry is negative. Third, for layers that offer no such division, such as convolutions, Deep Leakage from Gradients (DLG) searches for an input whose gradient matches the one observed. Fourth, the chapter asks which of these attacks survive when the client averages over a batch.

The running example comes in two sizes. A network with three inputs and two hidden units is small enough to compute by hand, and the division gives back its input \((0.5, 1, 0.2)\) exactly from each of its two hidden units. The experiments then use synthetic \(8\times8\) images and a network with 32 hidden units, whose gradient has 2,212 entries against 64 unknown pixels. There the division recovers an image to rounding error, DLG recovers one with about 13 correct digits after 600 steps, and in a batch of 4 the same division, applied at each unit that responds to only one image, still recovers all four images.

14.1 The reconstruction game

Before any attack can be judged, you need to know who sees what and what counts as success. This section fixes both for one round of federated training, in the vocabulary of Threat models and privacy games, and then fixes the network that every experiment uses.

The server is honest-but-curious in the sense of that chapter: it runs the protocol as specified and only analyses what it receives. Its access is the transcript. It sees each client’s own update, here the gradient the client sends, and it knows the architecture and every parameter of \(\theta\) because it chose them. The client’s loss is the average of the losses of its examples, and the derivative of an average is the average of the derivatives, so the gradient it sends is the average of its per-example gradients.

Definition 14.1 (The gradient reconstruction game) Fix a model \(\theta\), known to the server, and a population of labelled examples. The challenger, who holds the secret, is the client, and the adversary, who guesses it, is the server. The game has three steps.

  1. The challenger draws a batch of \(B\) labelled examples \((x_1, y_1), \dots, (x_B, y_B)\) from the population. The inputs are the secret.
  2. The client sends the gradient of its average loss with respect to all the parameters, \[g = \frac1B\sum_{i=1}^B\nabla_\theta\ell(\theta; x_i, y_i). \tag{14.1}\]
  3. The adversary sees \((\theta, g)\) and outputs reconstructions \(\hat x_1, \dots, \hat x_B\).

Each true input \(x\) is matched to its closest reconstruction \(\hat x\) in Euclidean distance (two inputs may share one), and the pair is scored by its relative error \(\|\hat x - x\|/\|x\|\).

The relative error is 0 for a perfect reconstruction and 1 for a mistake as large as the input itself. The matching is needed because an average does not change when you reorder the examples, so the gradient carries no record of which example came first. The attacks below either recover the client’s exact pixels or, for large batches, produce blends, images that mix several of the client’s inputs.

All experiments use one small network, written in NumPy. Its first fully connected layer gives one number per hidden unit, the unit’s pre-activation, and an activation is applied to each unit. A second fully connected layer turns the result into one score per class, called a logit. The softmax turns the logits into probabilities by exponentiating and normalizing, so that every probability is positive and they sum to 1. The loss is the cross-entropy, minus the log of the probability the model gives to the true label, which is small when the model is confidently right.

Definition 14.2 (The network) An input \(x \in \mathbb R^d\) has a label \(y\), one of \(K\) classes. It passes through a first layer with weights \(W_1 \in \mathbb R^{m\times d}\) and biases \(b_1\), one per hidden unit. An activation \(\sigma\) is applied to each of the \(m\) hidden units. A second layer with weights \(W_2 \in \mathbb R^{K\times m}\) and biases \(b_2\) gives one logit per class, and then \[a = W_1x + b_1, \quad h = \sigma(a), \quad z = W_2h + b_2, \quad p = \mathrm{softmax}(z), \quad \ell = -\ln p_y, \tag{14.2}\] where the softmax has entries \[p_k = \frac{e^{z_k}}{\sum_{k'}e^{z_{k'}}}. \tag{14.3}\] The backward signals are the rates at which the loss changes with each hidden unit’s pre-activation and with each logit, \(\gamma_1 = \partial\ell/\partial a\) and \(\gamma_2 = \partial\ell/\partial z\).

The activation \(\sigma\) is either the ReLU \(\max(a, 0)\), which passes positive values and replaces negative ones by 0, or the sigmoid \(1/(1 + e^{-a})\), which squashes every value smoothly into \((0, 1)\).

Example 14.1 The client’s inputs are synthetic \(8\times8\) grey-scale images, so \(d = 64\). Each shows one of \(K = 4\) shapes (a horizontal bar, a vertical bar, a diagonal and a square outline), shifted at random and with pixel noise. The network has \(m = 32\) hidden units and is at its random initialization, as in the first round of training. The first layer has \(64\cdot32\) weights and 32 biases, and the second has \(32\cdot4\) weights and 4 biases, so the network has \[64\cdot32 + 32 + 32\cdot4 + 4 = 2{,}212 \tag{14.4}\] parameters. The server receives 2,212 numbers about an example that has only 64 unknown pixels.

14.2 What a gradient is made of

Every attack in this chapter reads the input out of the gradient, so you first need to know where in the gradient the input sits. Two results answer this, one placing the input in every row of the weight gradient and one giving the backward signals that scale those rows.

The reason the input appears is the chain rule. The weight \(W_{jk}\) multiplies the input \(x_k\) and feeds only the output \(a_j\), so the loss changes with it at the rate at which the loss changes with \(a_j\), times \(x_k\). So the gradient of a weight is the signal flowing backward into its output times the input flowing forward into it. Collected over all \(j\) and \(k\), these products form a matrix whose \((j, k)\) entry is \(\gamma_jx_k\), called the outer product of \(\gamma\) and \(x\).

Proposition 14.1 (The gradient of a fully connected layer is an outer product) Let a fully connected layer compute \(a = Wx + b\) with \(W \in \mathbb R^{m\times d}\), and let the loss \(\ell\) depend on \(W\) and \(b\) only through \(a\), with backward signal \(\gamma = \partial\ell/\partial a\). Then \[\nabla_W\ell = \gamma\,x^\top, \qquad \nabla_b\ell = \gamma. \tag{14.5}\]

Proof.

  1. Each weight feeds one output. Written out, output \(j\) is \(a_j = \sum_kW_{jk}x_k + b_j\). The weight \(W_{jk}\) appears in \(a_j\) only, with coefficient \(x_k\), so \(\partial a_j/\partial W_{jk} = x_k\).
  2. The chain rule multiplies the two rates. The loss depends on \(W_{jk}\) only through \(a_j\), so \[\frac{\partial\ell}{\partial W_{jk}} = \frac{\partial\ell}{\partial a_j}\,\frac{\partial a_j}{\partial W_{jk}} = \gamma_jx_k, \tag{14.6}\] which is the \((j, k)\) entry of \(\gamma x^\top\).
  3. The bias has coefficient 1. The bias \(b_j\) enters \(a_j\) with coefficient 1, so the same rule gives \(\partial\ell/\partial b_j = \gamma_j\).

Row \(j\) of the outer product is the input multiplied by the number \(\gamma_j\). The signal \(\gamma\) depends on everything above the layer (the rest of the network, the loss, the label), but the factor \(x^\top\) does not. So the rest of the network can only rescale the rows, never change their direction.

To use Proposition 14.1 at the first layer you need its backward signal \(\gamma_1\), and the chain rule obtains it by sending the last layer’s signal \(\gamma_2\) back through the network. At the last layer the signal has a simple form. Raising the logit of a wrong class \(k\) raises the loss at the rate \(p_k\), the probability the model already gives that class, and raising the logit of the true class lowers the loss at the rate \(1 - p_y\). Each hidden unit then collects the logits’ signals, weighted by its connections to them, and multiplies by the slope of its activation.

Proposition 14.2 (The backward signals) For the network of Definition 14.2, write \(e_y\) for the one-hot vector of the label, with 1 in position \(y\) and 0 elsewhere, and \(\odot\) for the entrywise product of two vectors. Then \[\gamma_2 = p - e_y, \tag{14.7}\] so the entry of \(\gamma_2\) at the true label is negative and every other entry is positive, and \[\gamma_1 = (W_2^\top\gamma_2)\odot\sigma'(a). \tag{14.8}\]

Proof. The plan is to differentiate the loss in the logits, read off the signs, and then pass the result back through the second layer and the activation.

  1. Remove the fraction. Since \(p_y = e^{z_y}/\sum_ke^{z_k}\), taking minus its log gives \[\ell = -z_y + \ln\sum_ke^{z_k}. \tag{14.9}\]
  2. Differentiate in one logit. The first term depends only on \(z_y\), so it contributes \(-1\) when \(k = y\) and 0 otherwise. The second term is the log of a sum, whose derivative is the derivative of the sum, \(e^{z_k}\), divided by the sum itself, which is \(p_k\). Together, \[\frac{\partial\ell}{\partial z_k} = p_k - \mathbf 1[k = y], \tag{14.10}\] which is entry \(k\) of \(p - e_y\).
  3. Read off the signs. Every \(e^{z_k}\) is positive, so every \(p_k\) lies strictly between 0 and 1. The entry at the label is \(p_y - 1 < 0\), and every other entry is \(p_k > 0\).
  4. Pass back through the second layer. Logit \(k\) is \(z_k = \sum_jW_{2,kj}h_j + b_{2,k}\), so \(h_j\) enters each logit with coefficient \(W_{2,kj}\), and the chain rule sums over the logits: \[\frac{\partial\ell}{\partial h_j} = \sum_k\gamma_{2,k}W_{2,kj} = (W_2^\top\gamma_2)_j. \tag{14.11}\]
  5. Pass through the activation. The output \(h_j = \sigma(a_j)\) changes with \(a_j\) at the rate \(\sigma'(a_j)\), so multiplying step 4 by it gives entry \(j\) of Equation 14.8.

For ReLU the slope is \(\sigma'(a_j) = \mathbf 1[a_j > 0]\), which is 1 if the unit is switched on and 0 if it is switched off. So a unit that is switched off on an input has \(\gamma_{1,j} = 0\) and, by Proposition 14.1, a zero row in the first-layer weight gradient.

Example 14.2 Take \(d = 3\) inputs, \(m = 2\) ReLU units and \(K = 2\) classes, with \[W_1 = \begin{pmatrix}0.4 & -0.2 & 0.1\\ 0.3 & 0.5 & -0.4\end{pmatrix},\quad b_1 = \begin{pmatrix}0.1\\ -0.1\end{pmatrix},\quad W_2 = \begin{pmatrix}1 & -1\\ 0.5 & 0.5\end{pmatrix},\quad b_2 = 0, \tag{14.12}\] and the example \(x = (0.5, 1, 0.2)\) with label \(y = 1\), the first class. Table 14.2 walks through the forward pass, the backward pass and the gradient.

The first probability is \(p_1 = e^{-0.35}/(e^{-0.35} + e^{0.295})\), and dividing top and bottom by \(e^{-0.35}\) gives \(p_1 = 1/(1 + e^{0.645}) = 1/(1 + 1.906) = 0.3441\), so \(p = (0.3441, 0.6559)\). The two entries of \(\gamma_2\) sum to 0, and only the one at the true class is negative. Both units are on, since both entries of \(a\) are positive, so \(\gamma_1\) is just \(W_2^\top\gamma_2\), and the two rows of the weight gradient are \(-0.3279\) times \(x\) and \(0.9838\) times \(x\).

14.3 Exact recovery from a fully connected layer

The server sees \(g\). Is there any computation, without a search, that gives back the client’s input? For a fully connected first layer with a bias, the most common kind, there is one division, which Phong et al. (2018) pointed out for this federated setting.

By Proposition 14.1, row \(j\) of the first-layer weight gradient is \(x\) scaled by \(\gamma_{1,j}\), and entry \(j\) of the bias gradient is that same number, so dividing removes the scale.

Theorem 14.1 (Exact recovery from one example) Suppose the client sends the gradient of a single example, and the first layer is fully connected with a bias, \(a = W_1x + b_1\), whatever the layers above it and the loss. Then for every unit \(j\) with \((\nabla_{b_1}\ell)_j \ne 0\), \[x = \frac{(\nabla_{W_1}\ell)_{j,:}}{(\nabla_{b_1}\ell)_j}. \tag{14.13}\] Moreover, if \(\gamma_1 \ne 0\), the matrix \(\nabla_{W_1}\ell\) has rank one, and its row space is the line through \(x\).

Proof.

  1. Write out what the server sees. Proposition 14.1 applied to the first layer gives \((\nabla_{W_1}\ell)_{j,:} = \gamma_{1,j}\,x^\top\) and \((\nabla_{b_1}\ell)_j = \gamma_{1,j}\).
  2. Divide one by the other. When \(\gamma_{1,j} \ne 0\), the ratio is \(\gamma_{1,j}x^\top/\gamma_{1,j} = x^\top\). Nothing about the rest of the network enters, because the depth, the activations above, the loss and the label all sit inside the number \(\gamma_{1,j}\), and that number cancels.
  3. Read off the rank. All rows of \(\nabla_{W_1}\ell = \gamma_1x^\top\) are multiples of the same vector \(x^\top\), and at least one is nonzero when \(\gamma_1 \ne 0\). A matrix whose rows are all multiples of one nonzero vector has rank one, and its row space is spanned by that vector.

The attack is exact and needs no optimization, no prior knowledge of the data and no label. It also checks itself, because every usable unit must give the same answer.

Four things get in its way, and only one stops it fully. With ReLU, switched-off units give nothing, but one active unit is enough. Without a bias there is no denominator, but the rank-one structure still gives the direction of \(x\), so only the scale remains unknown, one number that matching gradients as in Section 14.5 finds. A convolutional first layer really breaks the outer-product form. It applies the same small filter at every position of the image, so its gradient is a sum of outer products over all the image patches, and only the search of Section 14.5 can undo it. A batch of more than one example also breaks the formula, but only partly, as Section 14.6 shows.

Example 14.3 In the hand network of Example 14.2, the server never sees \(a\), \(h\), \(z\) or \(p\). It sees only the gradient rows of Table 14.2. Dividing the first row by \(-0.3279\) and the second by \(0.9838\) gives \((0.5, 1, 0.2)\) both times, which is the input.

On the images, Figure 14.1 shows the attack on one input. Of the 32 ReLU units, 13 are switched on and have a nonzero bias gradient. Every one of the 13 ratios equals the image to a relative error of at most \(6.7\times10^{-17}\), which is rounding error. To check the rank, look at the singular values of \(\nabla_{W_1}\ell\). They measure how much of the matrix lies along each of its independent directions, so a rank-one matrix has exactly one that is not zero. The largest is \(1.6155\) and the second is \(9.5\times10^{-17}\) times the first, so the gradient is rank one, as Theorem 14.1 says.

14.4 Label recovery from the last layer

The gradient depends on the label too, and the label is often the most sensitive part: the diagnosis, the word typed next, the class of a photo. Zhao, Mopuri & Bilen (2020) noticed that the label can be read off the last layer in closed form. Their attack, iDLG (“improved DLG”), then searches only for the input, which makes the gradient-matching search of Section 14.5, below, easier and more reliable.

The next result gives three rules, one from the bias, one from the weights and one for batches. All three come from Proposition 14.2, which says that the last layer’s backward signal is a vector of probabilities with 1 subtracted at the true label. A batch gradient averages these vectors. Before the division by the batch size, the subtracted 1s in each position add up to the number of examples of that class.

Proposition 14.3 (Labels from the last layer) Let the network of Definition 14.2 keep its last-layer bias \(b_2\). For a single example, the label is the position of the only negative entry of the last-layer bias gradient, \[y = \arg\min_k(\nabla_{b_2}\ell)_k. \tag{14.14}\] If in addition the hidden activations satisfy \(h \ge 0\) and \(h \ne 0\), as for ReLU or the sigmoid, then row \(y\) of \(\nabla_{W_2}\ell\) is the only row whose entries are all non-positive, and the only row with a negative sum.

For a batch of \(B\) examples, write \(n_k\) for the number of examples of class \(k\) and \(p_{ik}\) for the probability the model gives class \(k\) on example \(i\). Then \[n_k = \sum_{i=1}^Bp_{ik} - B\,(\nabla_{b_2}\ell)_k. \tag{14.15}\]

Proof.

  1. The bias rule. Proposition 14.1 at the last layer gives \(\nabla_{b_2}\ell = \gamma_2\), and Proposition 14.2 gives \(\gamma_2 = p - e_y\), with entry \(p_y - 1 < 0\) at the label and \(p_k > 0\) elsewhere. The smallest entry is therefore at \(y\).
  2. The weight rule. Proposition 14.1 gives \((\nabla_{W_2}\ell)_{k,:} = \gamma_{2,k}\,h^\top\). With \(h \ge 0\), row \(y\) is a negative number times non-negative entries, so it is non-positive entrywise, and every other row is \(p_kh^\top \ge 0\). Summing a row multiplies \(\gamma_{2,k}\) by \(\sum_jh_j\), which is positive because \(h \ge 0\) and \(h \ne 0\), so the sum keeps the sign of \(\gamma_{2,k}\).
  3. The counts. The batch gradient is the average of the per-example ones, so \(\nabla_{b_2}\ell = \frac1B\sum_i(p_i - e_{y_i})\). The vector \(e_{y_i}\) has a 1 in position \(k\) exactly when example \(i\) has class \(k\), so \(\sum_ie_{y_i}\) counts the examples of each class, and entry \(k\) is \[(\nabla_{b_2}\ell)_k = \frac1B\Big(\sum_ip_{ik} - n_k\Big). \tag{14.16}\] Multiplying by \(B\) and solving for \(n_k\) gives Equation 14.15.

For one example the bias rule makes no errors, at any point of training, because the sign argument never depends on how good the model is. A confident model gives a tiny negative entry, which floating point hides only when \(p_y\) rounds to 1 and the entry becomes 0. That is one reason attacks are run on models early in training. Without a bias, and even for an activation such as tanh whose outputs can be negative, step 2 of the proof still shows that row \(y\) of \(\nabla_{W_2}\ell\) is a negative multiple of \(h\) and every other row a positive one, so the label’s row points the opposite way.

For a batch, the gradient leaks the label histogram. Equation 14.15 is exact, so the only unknown is the total prediction \(\sum_ip_{ik}\), and the attacker can estimate it well. If it holds data of its own from a similar population, which this attack assumes, it can run the model on them and average the predictions into a guess \(\bar p\), then replace the total by \(B\bar p_k\) and round. The true counts are integers, so rounding gives them exactly whenever the estimate of the total is off by less than \(\frac12\) for every class. The cruder guess \(\bar p_k = 1/K\) of evenly spread predictions does worse, because even an untrained network favours some classes over others.

Example 14.4 In the hand network of Example 14.2, the last-layer bias gradient is \(\gamma_2 = (-0.6559, 0.6559)\). Its smallest entry is the first, so the server reads off the label 1. On 1,000 random images and random networks, both the bias rule and the weight rule name the label correctly in a fraction 1.000 of the trials.

For a batch, take 16 images with true counts \((4, 2, 4, 6)\) over the four shapes. Table 14.3 reads them off the bias gradient of the 32-unit ReLU network, with three guesses for the total prediction in Equation 14.15.

With the averaged guess every estimate is within \(\frac12\) of the truth, the largest miss being \(4.19 - 4 = 0.19\), so rounding fixes it. With the uniform guess the first class is off by \(4 - 2.12 = 1.88\), and rounding cannot help.

Over 200 random batches and networks, the averaged guess gets all the rounded counts right in 1.000 of batches of 4 and 0.975 of batches of 16. For batches of 64 the rate falls to 0.525, and with the uniform guess the three rates are 0.925, 0.095 and 0.000. The rates fall because the error of the estimate is a sum of \(B\) deviations, one per example, and that sum grows with \(B\). At \(B = 16\) the largest error over the four classes, before rounding, has a median over batches of 0.233 with the averaged guess, against 1.102 with the uniform one.

14.5 Deep Leakage from Gradients

The closed forms need a fully connected layer with a bias. Most image models start with convolutions, and many architectures have layers that rescale or mix their inputs, such as normalization and attention, or no biases at all. Zhu, Liu & Han (2019) gave a generic attack that needs none of these: guess an input, compute its gradient, and move the guess until the gradients match. Zhu et al. also searched for a soft label, a probability vector standing in for the unknown label, and that joint search often failed. With the label fixed by Equation 14.14, the search is over the input only.

DLG measures how badly a guess matches by one number, the squared distance between the gradient the guessed batch would produce and the observed gradient, summed over all the gradient’s entries. It is zero for a perfect match and positive otherwise.

Definition 14.3 (Deep Leakage from Gradients) Given the model \(\theta\), the observed gradient \(g\) and the labels \(y_1, \dots, y_B\), write \(G(x') = \frac1B\sum_i\nabla_\theta\ell(\theta; x_i', y_i)\) for the gradient that a guessed batch \(x' = (x_1', \dots, x_B')\) would produce. The matching loss is \(R(x') = \|G(x') - g\|^2\), and DLG outputs \[\hat x_1, \dots, \hat x_B = \arg\min_{x_1', \dots, x_B'}R(x'), \qquad R(x') = \Big\|\frac1B\sum_{i=1}^B\nabla_\theta\ell(\theta; x_i', y_i) - g\Big\|^2, \tag{14.17}\] searching by a gradient method that starts from random noise and repeatedly moves the guess a little downhill on \(R\).

For a batch, the label rules of Proposition 14.3 give only the counts of each class, not which example has which label. That is enough, because the guesses are interchangeable: the attacker hands out the recovered labels to the guesses in any order, and each guess is then pulled towards a true example with its label.

Two facts make this a sensible search. The true batch scores the best value the matching loss can take, and the slope of the matching loss can be computed, as long as the network can be differentiated twice. The second fact needs the second derivatives because \(G\) is itself made of first derivatives of the network.

Proposition 14.4 (The true batch is a global minimizer) The true batch \((x_1, \dots, x_B)\) has \(R = 0\), the smallest value \(R\) takes. If the network is twice differentiable, then \(R\) is differentiable in the guess, with \[\nabla_{x'}R = 2\,J_G(x')^\top\big(G(x') - g\big), \tag{14.18}\] where \(J_G\) is the Jacobian of \(G\), the matrix of rates at which each gradient entry changes with each input pixel.

Proof.

  1. The true batch is a global minimizer. \(R\) is a squared length, so \(R \ge 0\) for every guess. Plugging in the true inputs reproduces \(g\) exactly, so \(R = 0\) there, and no guess can do better.
  2. The slope of a squared length. A squared length \(\|u\|^2\) changes with \(u\) at the rate \(2u\). Here \(u = G(x') - g\), and \(g\) does not depend on the guess.
  3. The chain rule passes the slope back to the guess. \(u\) changes with \(x'\) at the rates collected in \(J_G(x')\), so the chain rule multiplies the transpose of that matrix by \(2u\), which is Equation 14.18. The entries of \(J_G\) are derivatives of the gradient, so they are second derivatives of the network, and they exist because the network is twice differentiable.

The need for second derivatives is why Zhu et al. replaced ReLU by the sigmoid, and why the experiments here do the same. The gradient \(G\) contains the factor \(\sigma'(a)\) of Equation 14.8, and the search differentiates \(G\), so it differentiates that factor too. The ReLU’s slope is 0 or 1, constant on each side of zero, so the factor does not change as the guess moves, and the part of the slope of \(R\) that would flow through it is zero. The sigmoid’s slope varies smoothly, so that part is not lost.

Nobody builds \(J_G\) itself, which has one row per parameter and one column per pixel. Automatic-differentiation libraries instead differentiate the gradient computation, running backpropagation through the backward pass, which is called double backpropagation. That needs only a twice-differentiable network, not a fully connected first layer, so DLG also works for convolutional networks and on real images. Zhu et al. recover pictures from the CIFAR-100 image dataset and text tokens from single-example gradients.

Proposition 14.4 does not say that the search finds the true batch. \(R\) is not convex in the guess, and for such a function Optimization shows that a gradient method with a suitable step only drives the slope to zero. That gives a stationary point, where the surface is flat, which may or may not be the global minimum, so success is an empirical question. The final value of \(R\) tells you which case you are in: \(R = 0\) up to rounding means an exact match, while a value stuck well above zero means the search is stuck, and restarts or image priors, penalties that favour natural-looking images, may help.

The minimizer is also plausibly unique, since matching \(g\) imposes one equation per parameter, 2,212 here against \(64B\) unknown pixels, though that count is not a proof. For a single example the sigmoid network still has a fully connected first layer with a bias, so Theorem 14.1 shows that its gradient determines the input. Geiping et al. (2020) improved the search by comparing gradients by a cosine distance and penalizing differences between neighbouring pixels, and so recovered recognizable images from trained networks and from batches.

Example 14.5 The chapter’s script (Section 14.8) runs DLG on one image with the sigmoid network of 32 hidden units, computing the slope of Equation 14.18 by double backpropagation written out by hand. A finite-difference check, which nudges one pixel slightly and sees how much \(R\) changes, agrees with it to within \(1.2\times10^{-10}\). The search starts from uniform noise and runs 600 steps of the Adam optimizer, with learning rate 0.05 decaying linearly to 0. Adam is a variant of gradient descent that scales each pixel’s step by a running estimate of the size of that pixel’s gradient. The label comes from Equation 14.14.

By iteration 50 the image is visually correct, with 7.5% error, and by iteration 600 it is exact to about 13 digits (Figure 14.3). The matching loss falls about as the square of the error, which is what you should expect close to the answer. Near the true input \(x\) the map \(G\) is nearly linear, so the mismatch is about the Jacobian times the error, and its squared length is quadratic in the error: \[R(x') \approx \|J_G(x)(x' - x)\|^2. \tag{14.19}\] In the table, between iterations 50 and 100 the error shrinks by a factor \(0.075/0.0057 \approx 13\) and \(R\) by \(0.0025/0.000013 \approx 190\), close to \(13^2 \approx 170\).

14.6 Batches and averaging

Clients rarely send the gradient of one example. They send the average over a batch, or the change in parameters after several local training steps, which the end of this section treats. Averaging is often said to protect the individual examples, and this section measures that claim. Averaging does destroy the one-line formula of Equation 14.13, and it does make DLG harder. But the span of the batch survives, and so does every example to which some hidden unit responds alone.

The structure of a batch gradient follows from Proposition 14.1. Each example contributes one outer product, whose rows are multiples of its own input, so every row of the sum is a weighted combination of the \(B\) inputs.

Proposition 14.5 (The gradient of a batch) Take a batch of \(B\) examples and a fully connected first layer, and write \(\gamma_{1,i}\) for the backward signal of example \(i\) at that layer, with entries \(\gamma_{1,ij}\), one per unit \(j\). Then \[\nabla_{W_1}\ell = \frac1B\sum_{i=1}^B\gamma_{1,i}\,x_i^\top, \tag{14.20}\] so \(\nabla_{W_1}\ell\) has rank at most \(B\), and every row lies in \(\operatorname{span}\{x_1, \dots, x_B\}\). For every unit \(j\) with \((\nabla_{b_1}\ell)_j \ne 0\), the unit ratio is a weighted combination of the inputs, \[\frac{(\nabla_{W_1}\ell)_{j,:}}{(\nabla_{b_1}\ell)_j} = \sum_{i=1}^B\frac{\gamma_{1,ij}}{\sum_{i'}\gamma_{1,i'j}}\,x_i^\top, \tag{14.21}\] with weights that sum to 1 (some may be negative). It equals \(x_i\) exactly when \(\gamma_{1,ij} \ne 0\) and \(\gamma_{1,i'j} = 0\) for every \(i' \ne i\).

Proof.

  1. A sum of outer products. The batch gradient is the average of the per-example gradients, and by Proposition 14.1 each of those is \(\gamma_{1,i}x_i^\top\).
  2. Rank and span. Stack the \(x_i^\top\) as the rows of a matrix \(X\) with \(B\) rows, and the \(\gamma_{1,i}^\top\) as the rows of a matrix \(\Gamma\). The sum of outer products is then the product \(\frac1B\Gamma^\top X\). A product has rank at most that of either factor, and \(X\) has only \(B\) rows, so the rank is at most \(B\). Row \(j\) of the product is \(\frac1B\sum_i\Gamma_{ij}x_i^\top\), a combination of the inputs, so it lies in their span.
  3. The ratios. By Proposition 14.1 again, entry \(j\) of the bias gradient is \(\frac1B\sum_i\gamma_{1,ij}\). Dividing row \(j\) by it cancels the factors \(\frac1B\) and gives Equation 14.21. The weights are each example’s share of the same total, so they sum to 1, and if only \(\gamma_{1,ij}\) is nonzero the weight on \(x_i\) is 1 and all the others are 0.

For ReLU the condition for exact recovery, that only example \(i\) has a nonzero signal at unit \(j\), has a simple form. By Proposition 14.2, \(\gamma_{1,i'j} = 0\) whenever unit \(j\) is switched off on \(x_{i'}\), so a unit that is switched on for example \(i\) and for no other example gives back \(x_i\) exactly. Such a unit isolates example \(i\), and Section 14.7 asks how often that happens.

The span leaks even when nothing is isolated. When the gradient has rank \(B\), as it does for the batch of 4 below, its rows span exactly the span of the inputs. Every example is then a combination of \(B\) directions the attacker can read off the gradient, so a search such as DLG can look for each example as \(B\) unknown coefficients of those directions instead of \(d\) unknown pixels. That is 4 unknowns instead of 64 here, or of hundreds of thousands for real images.

Local steps do not help either. If the client takes several steps of stochastic gradient descent (SGD) on its batch and sends the total change in parameters, only the backward signals change from step to step. For one example and a learning rate \(\eta\), step \(s\) changes \(W_1\) by \(-\eta\gamma_1^{(s)}x^\top\) and \(b_1\) by \(-\eta\gamma_1^{(s)}\), where \(\gamma_1^{(s)}\) is that step’s backward signal. Summed over the steps, the change in \(W_1\) is the vector \(-\eta\sum_s\gamma_1^{(s)}\) times \(x^\top\), still rank one, and the change in \(b_1\) is that same vector. So the scale still cancels and Equation 14.13 still recovers \(x\) exactly.

Example 14.6 A batch of 4 images through the 32-unit ReLU network gives a first-layer gradient whose singular values, relative to the largest, are \(1.0\), \(0.84\), \(0.69\), \(0.039\) and then \(1.5\times10^{-16}\). Four directions are nonzero and the rest are rounding error, so the rank is 4, the most Proposition 14.5 allows. Every row lies in the span of the four images to within \(4.6\times10^{-16}\), and the unit ratios recover all 4 of the 4 images exactly.

DLG does much worse on batches of the same size. Table 14.5 runs it on the sigmoid network it needs for 6 random networks and batches of each size.

Batches of one and two are recovered to rounding error in most runs. From \(B = 4\) the median run gets stuck, with the matching loss near \(10^{-5}\) instead of \(10^{-27}\), and the reconstructions are blends of the batch (Figure 14.4). Two facts suggest that the search, not the information, is what fails. At \(B = 4\) there are only \(64\cdot4 = 256\) unknown pixels against 2,212 equations, though that count is not a proof. And on a ReLU network of the same width, which also averages four examples, the unit ratios recovered all four images, so averaging four examples does not by itself hide them.

14.7 How often a unit isolates an example

Every isolated example comes out exactly, so the share of a batch that a gradient exposes is the share isolated by at least one unit. How does that share depend on the batch size and on the width of the layer? To answer, you need a model of when units switch on, and the simplest one treats each unit’s response to each example as a fair coin.

For a single unit, the coin model is exact in one case. Suppose the first-layer bias is zero and the inputs are drawn from a distribution that is symmetric about zero, such as \(\mathcal N(0, I)\). Unit \(j\), with weights \((W_1)_{j,:}\), is on for \(x_i\) when \((W_1)_{j,:}\,x_i > 0\). With the weights fixed, symmetry makes this product equally likely to be positive or negative, it is exactly zero with probability 0, and independent inputs make the signs independent across the batch. So each unit’s on/off pattern over the batch is a sequence of fair coin flips. Different units look at the same inputs, though, so independence between units is only approximate, and real data are not symmetric at all.

Proposition 14.6 (Isolation under independent units) Take a ReLU first layer with \(m\) units and a batch of \(B\) examples. Suppose that each unit is on for each example with probability \(\frac12\), independently across examples and across units, and that every unit \(j\) active on an example \(i\) passes on a nonzero backward signal, \((W_2^\top\gamma_{2,i})_j \ne 0\), where \(\gamma_{2,i}\) is the last-layer signal of example \(i\). That fails only by coincidence. Then each example of the batch is recovered exactly by some unit ratio with probability \[P_{\text{iso}}(B, m) = 1 - (1 - 2^{-B})^m. \tag{14.22}\]

Proof.

  1. One unit. By Proposition 14.5 and the ReLU slope, unit \(j\) gives back \(x_i\) exactly when it is on for \(x_i\) and off for each of the other \(B - 1\) examples, since an active unit has a nonzero signal by hypothesis. Each of these \(B\) events has probability \(\frac12\), and they are independent, so their probability together is \(2^{-B}\).
  2. Many units. The example is missed only if all \(m\) units miss it. The units are independent by hypothesis, so this has probability \((1 - 2^{-B})^m\), and subtracting from 1 gives Equation 14.22.

The formula pits an exponential in \(B\) against a count that grows linearly in \(m\). A unit isolates a given example with probability \(2^{-B}\), so among \(m\) units the expected number that isolate it is \(m2^{-B}\), and almost every example is isolated when \(m\) is much larger than \(2^B\). To find the width that gives an even chance, require the miss probability \((1 - 2^{-B})^m\) to be at most \(\frac12\) and take logs. The log of \(1 - 2^{-B}\) is negative, so dividing by it flips the inequality and gives \[m \ge \frac{\ln2}{-\ln(1 - 2^{-B})}. \tag{14.23}\] At \(B = 10\) the denominator is \(-\ln(1 - 2^{-10}) = 0.000977\), close to \(2^{-10}\) itself, and the bound is \(0.6931/0.000977 \approx 709.4\), so you need \(m \ge 710\) units. Real first layers have thousands of units, so if units behaved like these coins, batches of 10 would not be safe from this attack.

Data whose examples resemble one another, such as images of a few shapes, are easier for the attacker, not harder. With such images, a unit tends to fire on many examples of a batch or on few. The number of examples it fires for is more spread out than the coin model predicts, which statisticians call overdispersion. In particular some units fire only on rare inputs, and when such a unit fires on a large batch it usually fires on just one example, so isolation is much more common at large \(B\). Take one extreme model, in which each unit has its own firing rate \(r\), drawn uniformly between 0 and 1. A unit with rate \(r\) isolates a given example with probability \(r(1 - r)^{B-1}\), and averaging over \(r\) gives \(\int_0^1r(1 - r)^{B-1}\,dr = 1/(B(B + 1))\). That shrinks only like \(1/B^2\) instead of halving with each extra example.

The game of this chapter has an honest-but-curious server. A malicious server does better still, because it chooses \(\theta\) to attack rather than at random. It can plant first-layer units that fire on rare inputs only (“trap weights”, Boenisch et al. 2023), or that sort inputs into bins by a feature such as brightness (Fowl et al. 2022), so that most examples of even a large batch are isolated by construction.

Example 14.7 For the batch of 4 in Example 14.6, the network has \(m = 32\) units and \(1 - 2^{-4} = 15/16\), so Equation 14.22 predicts \[P_{\text{iso}}(4, 32) = 1 - (15/16)^{32} = 1 - e^{32\ln(15/16)} = 1 - e^{-2.065} = 0.873 \tag{14.24}\] per example under independence. All 4 of the 4 images were recovered. Table 14.6 compares Equation 14.22 with simulation over a range of widths and batch sizes, with 20 random networks and batches per cell (Figure 14.5 shows the full range).

For Gaussian inputs the formula matches to within the simulation noise, overestimating slightly in seven of the eight rows because units see the same inputs, so they are not quite independent. For images the formula is far too reassuring. At \(B = 16\) it predicts that 1.6% of the batch is exposed in the 1024-unit network, and 69.1% is.

At \(B = 4\), by contrast, the images are recovered less often than the formula predicts, 0.838 against 0.984 for \(m = 64\). Overdispersion cuts both ways. The same spread that makes “on for exactly one image” more common at large \(B\) also makes “on for all four images” and “on for none” common at small \(B\), and units like that isolate nothing.

9  Sparse vector

Author

Manuel V. Loureiro

Published

Version 2026-10-30

Queries often arrive one at a time, and each must be answered before the next is seen. Under differential privacy (DP), answering each of them with its own noise makes the error grow polynomially with the number of queries. But often the analyst only needs to know which queries exceed a threshold, and few of them do. This chapter shows, with the sparse vector technique, that the cost then depends on the number of large queries and only logarithmically on the total. Its privacy proof rests on noise on the threshold as well as on the queries. At the end, the technique turns private multiplicative weights into an algorithm that answers queries as they arrive.

9.1 Answering queries online

The setting is a stream of queries \(f_1, f_2, \dots, f_k \colon \mathcal X^n \to \mathbb R\), each with sensitivity at most \(1\). Two datasets \(D\) and \(D'\) are neighbours, written \(D \sim D'\), when they differ by the replacement of one record. Sensitivity at most \(1\) means that \(|f_i(D) - f_i(D')| \le 1\) for every such pair. Counting queries, which count the records with some property, are the typical example. Query \(f_i\) arrives at step \(i\) and must be answered before \(f_{i+1}\) is revealed.

The Laplace mechanism answers each query with noise from the Laplace distribution \(\mathrm{Lap}(b)\) of scale \(b\), whose density at \(z\) is \(e^{-|z|/b}/(2b)\). For a sensitivity-\(1\) query it is \(\varepsilon\)-DP when \(b = 1/\varepsilon\), and its tails are \(\Pr[|\mathrm{Lap}(b)| \ge tb] = e^{-t}\). Under pure DP with a total budget \(\varepsilon\), basic composition forces the scale \(k/\varepsilon\) on each of \(k\) answers, so the error is of order \(k/\varepsilon\). Under approximate DP, the advanced composition theorem brings this down to order \(\sqrt{k\ln(1/\delta)}/\varepsilon\). Both are polynomial in \(k\), and in the worst case no algorithm that answers every query can do much better.

A weaker question has a cheaper answer: which queries are large? If all \(k\) queries were known in advance, the exponential mechanism with score \(f_i(D)\) would pick a query whose value is within \(2(\ln k + t)/\varepsilon\) of the largest, except with probability \(e^{-t}\). Repeating it \(c\) times with budget \(\varepsilon/c\) each finds \(c\) large queries with error of order \(c\ln k/\varepsilon\), or \(\sqrt{c\ln(1/\delta)}\ln k/\varepsilon\) with advanced composition. That is logarithmic in \(k\), but it needs the whole list. Online, the first query cannot be compared with queries not yet seen, so the question becomes absolute.

Given a public threshold \(\tau\), report the first \(c\) queries in the stream with \(f_i(D) \ge \tau\), and stop.

The idea is to run the Laplace mechanism on each query and report only whether the noisy value exceeds a noisy threshold \(\hat\tau\), not \(\tau\) itself. The details matter, because several published variants are not private.

9.2 AboveThreshold

The case \(c = 1\) finds the first large query and halts. AboveThreshold draws one noisy threshold at the start, compares each noisy query with it, and answers with one of two symbols. The symbol \(\top\) means “above the threshold” and \(\bot\) means “below”.

Definition 9.1 (AboveThreshold) The inputs are a dataset \(D\), a stream of sensitivity-\(1\) queries \(f_1, f_2, \dots\), a threshold \(\tau \in \mathbb R\) and \(\varepsilon > 0\).

  1. Draw \(\hat\tau = \tau + \mathrm{Lap}(2/\varepsilon)\).
  2. For each query \(f_i\) in turn, draw \(\nu_i \sim \mathrm{Lap}(4/\varepsilon)\). If \(f_i(D) + \nu_i \ge \hat\tau\), output \(\top\) and halt. Otherwise output \(\bot\).

All noise draws are independent.

Nothing in the algorithm depends on the number of queries, so the stream may even be infinite, and the privacy guarantee does not change. The accuracy guarantee does, because more noise draws mean a larger largest one.

The queries can be fixed in advance, or an analyst who sees the earlier answers can choose them. Before the algorithm halts every answer is \(\bot\), so in the second case each query is still a fixed function of the analyst’s own coins, which do not depend on the dataset. The proof below applies to the stream fixed by each value of those coins, and averaging the inequality over the coins keeps it.

Theorem 9.1 AboveThreshold is \(\varepsilon\)-DP.

Proof.

  1. Fix neighbours \(D \sim D'\) and a stream, and write \(Y\) and \(Y'\) for the outputs on \(D\) and \(D'\). The outputs are \(y = \bot^{t-1}\top\), which halts at query \(t\), and the output that never halts: \(\bot^k\) for a stream of finite length \(k\), or \(\bot^\infty\) for an infinite one. These form a countable set, so by the pointwise lemma for discrete outputs it suffices to show \(\Pr[Y = y] \le e^\varepsilon\Pr[Y' = y]\) for each of them.
  2. Fix the noise of the first \(t-1\) queries. Condition on \(\nu_i = v_i\) for \(i < t\), the same values on both datasets, and let

\[ g(D) = \max_{i < t}\big(f_i(D) + v_i\big), \tag{9.1}\]

with \(g = -\infty\) if \(t = 1\). With the \(v_i\) fixed, \(g\) is a number, not a random variable. Each \(f_i\) has sensitivity \(1\), so \(|g(D) - g(D')| \le 1\). 3. The output is \(y\) exactly when every earlier query falls below \(\hat\tau\) and query \(t\) does not, that is, when \(g(D) < \hat\tau \le f_t(D) + \nu_t\). Write \(\phi_2\) and \(\phi_4\) for the densities of \(\hat\tau\) and \(\nu_t\), whose subscripts recall the scales \(2/\varepsilon\) and \(4/\varepsilon\). Then

\[ \Pr[Y = y] = \int\!\!\int \phi_2(u)\,\phi_4(v)\,\mathbf 1\big[g(D) < u \le f_t(D) + v\big]\,\mathrm d u\,\mathrm d v . \tag{9.2}\]

  1. Change variables to move from \(D\) to \(D'\). Substitute

\[ u = u' + g(D) - g(D'), \qquad v = v' + g(D) - g(D') + f_t(D') - f_t(D). \tag{9.3}\]

This is a shift, so \(\mathrm d u\,\mathrm d v = \mathrm d u'\,\mathrm d v'\). The condition \(g(D) < u\) becomes \(g(D') < u'\), and \(u \le f_t(D) + v\) becomes \(u' \le f_t(D') + v'\), so the indicator becomes \(\mathbf 1[g(D') < u' \le f_t(D') + v']\). 5. Pay for the shifts. By step 2, \(|u - u'| \le 1\). By step 2 and the sensitivity of \(f_t\), \(|v - v'| \le 2\). A Laplace density of scale \(b\) changes by at most a factor \(e^{s/b}\) when its argument moves by \(s\), so \(\phi_2(u) \le e^{\varepsilon/2}\phi_2(u')\) and \(\phi_4(v) \le e^{2\varepsilon/4}\phi_4(v') = e^{\varepsilon/2}\phi_4(v')\). Hence

\[ \Pr[Y = y] \le e^{\varepsilon}\int\!\!\int \phi_2(u')\,\phi_4(v')\,\mathbf 1\big[g(D') < u' \le f_t(D') + v'\big]\,\mathrm d u'\,\mathrm d v' = e^\varepsilon\Pr[Y' = y], \tag{9.4}\]

where both probabilities are conditional on the fixed \(v_1,\dots,v_{t-1}\). 6. The \(v_i\) have the same distribution on both datasets, so averaging step 5 over them gives the unconditional inequality. 7. The output that never halts. It occurs exactly when \(\hat\tau > \sup_i(f_i(D) + \nu_i)\), the supremum over all queries of the stream. Fixing all \(\nu_i\) makes this supremum a number \(g(D)\), possibly \(+\infty\), with \(|g(D) - g(D')| \le 1\) when it is finite, and the output has probability \(0\) on both datasets when it is not. Shifting \(u\) by at most \(1\) as in steps 4 and 5 gives the factor \(e^{\varepsilon/2} \le e^\varepsilon\).

The two noises do different jobs. The noise on \(\hat\tau\) pays, in one draw, for all the \(\bot\) answers: the proof fixes their noise and absorbs the change in their maximum by shifting the threshold. The noise \(\nu_t\) pays for the single \(\top\). So the privacy cost does not grow with the number of \(\bot\) answers.

The output carries no numbers, so accuracy means making no mistakes, with some slack around the threshold.

Definition 9.2 (Accuracy for threshold answers) Let an algorithm answer a stream of queries \(f_1, f_2, \dots\) with \(\top\) or \(\bot\), compared with a threshold \(\tau\), and write \(a_i\) for its answer to \(f_i\). Let \(\alpha \ge 0\) be a slack and \(\beta \in (0,1)\) a failure probability. The algorithm is \((\alpha,\beta)\)-accurate on \(D\) if, with probability at least \(1-\beta\), every answered query satisfies

\[ a_i = \top \implies f_i(D) \ge \tau - \alpha \qquad\text{and}\qquad a_i = \bot \implies f_i(D) \le \tau + \alpha . \tag{9.5}\]

In words, no query more than \(\alpha\) below the threshold gets a \(\top\), and no query more than \(\alpha\) above it gets a \(\bot\). AboveThreshold meets this definition with a slack \(\alpha\) that grows only with the logarithm of the number of queries. The theorem also asks that every query before the last be at least \(\alpha\) below the threshold, so that the algorithm does not halt early.

Theorem 9.2 (Accuracy of AboveThreshold) Let \(\beta \in (0,1)\), and let \(f_1, \dots, f_k\) be a stream with \(f_i(D) \le \tau - \alpha\) for every \(i < k\), where

\[ \alpha = \frac{8\big(\ln k + \ln(2/\beta)\big)}{\varepsilon}. \tag{9.6}\]

Then AboveThreshold is \((\alpha,\beta)\)-accurate on \(D\), and with probability at least \(1-\beta\) it does not halt before query \(k\).

Proof.

  1. The good event. Let \(G\) be the event that \(|\hat\tau - \tau| < \alpha/2\) and \(|\nu_i| < \alpha/2\) for every \(i \le k\).
  2. Accuracy on \(G\). If \(a_i = \top\), then \(f_i(D) \ge \hat\tau - \nu_i > (\tau - \alpha/2) - \alpha/2 = \tau - \alpha\). If \(a_i = \bot\), then \(f_i(D) < \hat\tau - \nu_i < \tau + \alpha\).
  3. No early halt on \(G\). By step 2, a \(\top\) at query \(i\) needs \(f_i(D) > \tau - \alpha\), which the hypothesis rules out for \(i < k\).
  4. \(G\) is likely. The threshold noise has scale \(2/\varepsilon\), so the tail formula gives \(\Pr[|\hat\tau - \tau| \ge \alpha/2] = e^{-\varepsilon\alpha/4}\). Each \(\nu_i\) has scale \(4/\varepsilon\), so a union bound gives \(\Pr[\max_{i\le k}|\nu_i| \ge \alpha/2] \le k e^{-\varepsilon\alpha/8}\).
  5. With Equation 9.6, \(ke^{-\varepsilon\alpha/8} = k\cdot\frac{1}{k}\cdot\frac{\beta}{2} = \beta/2\). Also \(e^{-\varepsilon\alpha/4} = (\beta/(2k))^2 \le \beta/2\). So \(\Pr[G] \ge 1-\beta\).

The error grows only logarithmically in \(k\), like that of the exponential mechanism, but the queries can arrive online.

Example 9.1 Take \(k = 10^6\) counting queries, \(\varepsilon = 1\) and \(\beta = 0.05\). Then Equation 9.6 gives \(\alpha = 8(\ln 10^6 + \ln 40) = 8(13.82 + 3.69) = 140.0\). On a dataset of \(n = 10^5\) records, a query is placed correctly unless its count lies within \(140\) of the threshold. Answering every query with the Laplace mechanism and basic composition would instead add noise of scale \(10^6\), ten times the size of the dataset.

9.3 Sparse vector

To find \(c\) large queries, restart AboveThreshold after each \(\top\), with a fresh threshold, until \(c\) of them have been found.

Definition 9.3 (Sparse vector) The inputs are those of AboveThreshold, a count \(c \ge 1\) of \(\top\) answers to find, and a parameter \(\delta\), with either \(\delta = 0\) or \(\delta \in (0,1/2]\). Set the Laplace noise scale \(b\) to

\[ b = \frac{2c}{\varepsilon} \ \text{ if } \delta = 0, \qquad b = \frac{\sqrt{32c\ln(1/\delta)}}{\varepsilon} \ \text{ if } \delta > 0 . \tag{9.7}\]

  1. Draw \(\hat\tau = \tau + \mathrm{Lap}(b)\) and set \(\mathrm{count} = 0\).
  2. For each query \(f_i\) in turn, draw \(\nu_i \sim \mathrm{Lap}(2b)\). If \(f_i(D) + \nu_i < \hat\tau\), output \(\bot\). Otherwise output \(\top\) and add \(1\) to \(\mathrm{count}\). If \(\mathrm{count} = c\), halt. If not, draw a fresh \(\hat\tau = \tau + \mathrm{Lap}(b)\) and continue.

Between two \(\top\) answers the algorithm runs AboveThreshold with parameter \(\varepsilon' = 2/b\), whose noise scales are \(2/\varepsilon' = b\) and \(4/\varepsilon' = 2b\). The fresh threshold matters, because reusing \(\hat\tau\) after a \(\top\) would break this equivalence, and with it the proof. With the equivalence, sparse vector is a composition of \(c\) runs of AboveThreshold, and its privacy follows from the composition theorems.

Theorem 9.3 Sparse vector with \(\delta = 0\) is \(\varepsilon\)-DP for every \(\varepsilon > 0\). With \(\varepsilon \in (0,1]\) and \(\delta \in (0,1/2]\) it is \((\varepsilon,\delta)\)-DP.

Proof.

  1. The output is the concatenation of at most \(c\) runs of AboveThreshold, each with parameter \(\varepsilon' = 2/b\) and fresh noise. Each run takes the rest of the stream, which may depend on the earlier outputs, so the whole is an adaptive composition of \(c\) mechanisms. A run that never starts, because the algorithm halted, has a fixed output. Each run is \(\varepsilon'\)-DP by Theorem 9.1.
  2. If \(\delta = 0\), then \(\varepsilon' = \varepsilon/c\), and basic composition gives \(c\varepsilon' = \varepsilon\).
  3. If \(\delta > 0\), then \(\varepsilon' = 2\varepsilon/\sqrt{32c\ln(1/\delta)} = \varepsilon/\big(2\sqrt{2c\ln(1/\delta)}\big)\). The budget-splitting lemma says that \(m\) adaptively composed mechanisms, each \(\varepsilon/(2\sqrt{2m\ln(1/\delta)})\)-DP, are together \((\varepsilon,\delta)\)-DP when \(\varepsilon \le 1\) and \(\delta \le 1/2\). Apply it with \(m = c\).

Accuracy is proved as for AboveThreshold. The only change is that the union bound now runs over every threshold drawn, one per run, as well as over the noise on each query.

Theorem 9.4 (Accuracy of sparse vector) Let \(\beta \in (0,1)\), let \(f_1, \dots, f_k\) be a stream, and let

\[ \alpha = 4b\ln(2k/\beta) . \tag{9.8}\]

With probability at least \(1-\beta\), every answered query satisfies the two implications of Definition 9.2. If moreover fewer than \(c\) of the queries have \(f_i(D) > \tau - \alpha\), the algorithm answers all \(k\) queries. In terms of the parameters, the accuracy is

\[ \alpha = \frac{8c\big(\ln k + \ln(2/\beta)\big)}{\varepsilon} \ \text{ if } \delta = 0, \qquad \alpha = \frac{\sqrt{512\,c\ln(1/\delta)}\,\big(\ln k + \ln(2/\beta)\big)}{\varepsilon} \ \text{ if } \delta > 0 . \tag{9.9}\]

Proof.

  1. Let \(G\) be the event that every threshold drawn and every \(\nu_i\) with \(i \le k\) lies within \(\alpha/2\) of its centre. On \(G\), steps 2 and 3 of the proof of Theorem 9.2 apply to each query, with whichever threshold is current. So the implications hold, and a \(\top\) needs \(f_i(D) > \tau - \alpha\).
  2. If fewer than \(c\) queries have \(f_i(D) > \tau-\alpha\), then on \(G\) there are fewer than \(c\) answers \(\top\), and the algorithm never halts.
  3. The query noise has scale \(2b\), and \(\alpha/(4b) = \ln(2k/\beta)\). A union bound over the \(k\) draws bounds its failure by \(k e^{-\alpha/(4b)} = \beta/2\).
  4. At most \(k+1\) thresholds are drawn, each with scale \(b\). Their failure is at most \((k+1)e^{-\alpha/(2b)} = (k+1)\beta^2/(4k^2) \le \beta/2\), since \(k + 1 \le 2k\) and \(\beta \le 1\).
  5. Substituting the two values of \(b\) into \(4b\ln(2k/\beta)\) gives Equation 9.9, because \(4\sqrt{32} = \sqrt{512}\).

With \(c = 1\) and \(\delta = 0\) this is Theorem 9.2 again. The error is polynomial in the number \(c\) of large queries and logarithmic in the total number \(k\). So sparse vector can scan a very long stream, as long as few of its queries are large.

9.4 Numeric sparse vector

Sparse vector already pays in proportion to the number \(c\) of large queries. A noisy value for each of those \(c\) queries takes \(c\) more Laplace mechanisms, which cost the same order of budget. So sparse vector can also release the values of the large queries for a constant factor.

Definition 9.4 (Numeric sparse vector) Run sparse vector with \(\delta = 0\) and budget \(\varepsilon/2\), so \(b = 4c/\varepsilon\). Whenever it would output \(\top\) for query \(f_i\), output instead \(a_i = f_i(D) + \mathrm{Lap}(2c/\varepsilon)\), with fresh noise.

Each answer is now either \(\bot\) or a number. The guarantee combines the two implications of Definition 9.2 with an error bound on every released number.

Theorem 9.5 Numeric sparse vector is \(\varepsilon\)-DP. Let \(f_1, \dots, f_k\) be a stream, \(\beta\in(0,1)\) and \(\alpha = 16c\ln(4k/\beta)/\varepsilon\). With probability at least \(1-\beta\), every answered query satisfies the following, where \(a_i \in \mathbb R\) means that the answer to \(f_i\) is a released number:

\[ a_i = \bot \implies f_i(D) \le \tau + \alpha, \qquad a_i \in \mathbb R \implies f_i(D) \ge \tau - \alpha \ \text{ and } \ |a_i - f_i(D)| \le \alpha , \tag{9.10}\]

and if fewer than \(c\) queries have \(f_i(D) > \tau - \alpha\), all \(k\) are answered.

Proof.

  1. Privacy. The algorithm is an adaptive composition of at most \(c\) runs of AboveThreshold, each with parameter \(2/b = \varepsilon/(2c)\), and at most \(c\) Laplace mechanisms. Each Laplace mechanism measures one sensitivity-\(1\) query, chosen from the earlier outputs, with scale \(2c/\varepsilon\), so it is \(\varepsilon/(2c)\)-DP. Basic composition over the \(2c\) mechanisms gives \(\varepsilon\).
  2. Accuracy of the labels. Theorem 9.4 with \(b = 4c/\varepsilon\) and failure probability \(\beta/2\) gives accuracy \(4b\ln(4k/\beta) = \alpha\) for the labels, and no early halt, with probability at least \(1-\beta/2\).
  3. Accuracy of the values. At most \(k\) values are released, one per query. By the tail formula and a union bound, some noise exceeds \(\alpha\) with probability at most \(k\,e^{-\alpha\varepsilon/(2c)} = k\,(\beta/(4k))^8 \le \beta/2\).

The fresh noise in the released value matters. Releasing \(f_i(D) + \nu_i\), the value already compared with the threshold, is not private, and published variants that did so were wrong.

9.5 Online private multiplicative weights

The previous chapter built private multiplicative weights for a fixed set of linear queries \(q \colon \mathcal X \to [0,1]\), with \(q(D) = \frac1n\sum_i q(x_i)\). This section uses four of its facts. For a distribution \(p\) on \(\mathcal X\), write \(\langle q, p\rangle = \sum_x q(x)p(x)\) for the average of \(q\) under \(p\). The histogram \(p_D\) of the dataset, the fraction of records equal to each \(x\), satisfies \(q(D) = \langle q, p_D\rangle\). Multiplicative weights over the experts \(\mathcal X\) with learning rate \(\eta\) and losses \(s_tq^t\), where \(s_t\) is the sign of the error \(\langle q^t, p^t\rangle - q^t(D)\), has total error at most \(\eta U + \ln|\mathcal X|/\eta\) after \(U\) updates. And the offline algorithm used the exponential mechanism to find a query with a large error.

Online, the exponential mechanism cannot be used, because the queries arrive one at a time, so sparse vector replaces it. The algorithm keeps a distribution \(\hat p\) and answers each query from it while it is accurate. When sparse vector reports a large error, the algorithm answers with a noisy true value and updates \(\hat p\).

These queries have sensitivity \(1/n\), not \(1\). Sparse vector on \(f_i/\Delta\) with threshold \(\tau/\Delta\) handles sensitivity \(\Delta\). It is the same algorithm with every noise scale multiplied by \(\Delta\), so it has the same privacy and \(\Delta\) times the accuracy \(\alpha\). The algorithm runs this rescaled sparse vector on the errors of \(\hat p\), with threshold \(\alpha/2\). Its count \(c\) of large errors is set to the bound on the number of updates from the previous chapter, and \(\varepsilon_0\) is the budget of each of the \(2c\) mechanisms it may run.

Definition 9.5 (Online private multiplicative weights) The inputs are a dataset \(D\in\mathcal X^n\), a stream of linear queries \(f_1, f_2, \dots\), an accuracy \(\alpha \in (0,1]\), and \(\varepsilon \in (0,1]\) and \(\delta\in(0,1/2]\). Set

\[ c = \left\lceil\frac{64\ln|\mathcal X|}{\alpha^2}\right\rceil, \qquad \eta = \frac\alpha8, \qquad \varepsilon_0 = \frac{\varepsilon}{4\sqrt{c\ln(1/\delta)}} , \tag{9.11}\]

let \(\hat p\) be uniform on \(\mathcal X\), set \(\mathrm{count} = 0\), and draw \(\hat\tau = \alpha/2 + \mathrm{Lap}(2/(\varepsilon_0n))\). For each query \(f_i\) in turn:

  1. Let \(e_i = |\langle f_i, \hat p\rangle - f_i(D)|\) and draw \(\nu_i \sim \mathrm{Lap}(4/(\varepsilon_0n))\).
  2. If \(e_i + \nu_i < \hat\tau\), answer \(\langle f_i, \hat p\rangle\).
  3. Otherwise answer \(a_i = f_i(D) + Z_i\) with \(Z_i \sim\mathrm{Lap}(1/(\varepsilon_0 n))\). Let \(s_i\) be the sign of \(\langle f_i, \hat p\rangle - a_i\), update \(\hat p(x) \propto \hat p(x)\big(1 - \eta s_if_i(x)\big)\), and add \(1\) to \(\mathrm{count}\). If \(\mathrm{count} = c\), halt. Otherwise draw a fresh \(\hat\tau = \alpha/2 + \mathrm{Lap}(2/(\varepsilon_0n))\).

Steps 1 to 3 follow numeric sparse vector, run on the errors \(e_i\) with threshold \(\alpha/2\), except that the fresh measurement in step 3 is of \(f_i(D)\) rather than of \(e_i\). The answer in step 2 uses only \(\hat p\), which depends on the earlier outputs alone, so it costs no privacy.

Theorem 9.6 Online private multiplicative weights is \((\varepsilon,\delta)\)-DP.

Proof.

  1. Between two updates \(\hat p\) is fixed, so the errors \(e_i\) form a stream of queries determined by the earlier outputs and the analyst. Each \(e_i\) has sensitivity \(1/n\), since \(\langle f_i,\hat p\rangle\) does not depend on \(D\) and \(f_i(D)\) changes by at most \(1/n\).
  2. Each stretch between updates is therefore AboveThreshold with parameter \(\varepsilon_0\), rescaled to sensitivity \(1/n\), and so \(\varepsilon_0\)-DP by Theorem 9.1. Each measurement in step 3 is the Laplace mechanism on a query of sensitivity \(1/n\) with scale \(1/(\varepsilon_0n)\), so it is also \(\varepsilon_0\)-DP. The answers of step 2 and the updates are post-processing.
  3. There are at most \(c\) stretches and \(c\) measurements, so the algorithm is an adaptive composition of \(2c\) mechanisms, each \(\varepsilon_0\)-DP. Since \(\varepsilon_0 = \varepsilon/(2\sqrt{2\cdot 2c\ln(1/\delta)})\), the budget-splitting lemma with \(m = 2c\) mechanisms makes it \((\varepsilon,\delta)\)-DP.

Accuracy follows the proof for the offline algorithm. When all the noise is small, every answer from \(\hat p\) is accurate, every measured answer is accurate, and every update makes progress, so the count of updates never reaches \(c\).

Theorem 9.7 (Accuracy of online private multiplicative weights) Let \(|\mathcal X|\ge 2\), \(\beta\in(0,1)\) and a stream of \(k\) queries, and let the other parameters be as in Definition 9.5. If

\[ n \ge \frac{128\sqrt{c\ln(1/\delta)}\,\ln\big((2c+k)/\beta\big)}{\alpha\varepsilon}, \tag{9.12}\]

then with probability at least \(1-\beta\) the algorithm answers all \(k\) queries, each within \(\alpha\) of \(f_i(D)\).

Proof.

  1. The good event. Let \(G\) be the event that every threshold noise, every \(\nu_i\) and every \(Z_i\) is less than \(\alpha/8\) in absolute value. These are at most \(2c + k\) draws, because there are at most \(c\) thresholds and \(c\) measurements. The widest scale is \(4/(\varepsilon_0n)\), so each draw fails with probability at most \(e^{-\alpha\varepsilon_0n/32}\). Condition Equation 9.12 is the same as \(\alpha\varepsilon_0n/32 \ge \ln((2c+k)/\beta)\), by the value of \(\varepsilon_0\). A union bound gives \(\Pr[G] \ge 1-\beta\), and the rest assumes \(G\).
  2. Answers from \(\hat p\). In step 2, \(e_i < \hat\tau - \nu_i < \alpha/2 + \alpha/8 + \alpha/8 = 3\alpha/4\), so the answer is within \(\alpha\).
  3. Measured answers. In step 3, \(|a_i - f_i(D)| = |Z_i| < \alpha/8\). Also \(e_i \ge \hat\tau - \nu_i > \alpha/2 - \alpha/4 = \alpha/4\). The difference \(\langle f_i,\hat p\rangle - a_i\) is the true error minus \(Z_i\), and \(|Z_i| < \alpha/8 < e_i\), so \(s_i\) is the sign of the true error.
  4. Few updates. By step 3, the updates are those of multiplicative weights for queries with \(\eta = \alpha/8\), and each has error above \(\alpha/4\). If there are \(U\) of them, the regret bound gives

\[ \frac\alpha4U < \frac\alpha8U + \frac{8\ln|\mathcal X|}{\alpha}, \qquad\text{that is,}\qquad U < \frac{64\ln|\mathcal X|}{\alpha^2} \le c . \tag{9.13}\]

So the count never reaches \(c\), the algorithm never halts, and all \(k\) queries are answered.

As in the previous chapter, \(c \le 66\ln|\mathcal X|/\alpha^2\). So condition Equation 9.12 asks for

\[ n = O\!\left(\frac{\sqrt{\ln|\mathcal X|\,\ln(1/\delta)}\;\ln\frac{k + \ln|\mathcal X|/\alpha^2}{\beta}}{\alpha^2\varepsilon}\right) \tag{9.14}\]

records. This matches the offline algorithm, with the length \(k\) of the stream in place of the number \(|\mathcal Q|\) of queries.

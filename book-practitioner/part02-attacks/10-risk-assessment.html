18  Pre-release privacy risk assessment

18.1 Why this matters

Before a model or a table leaves your hands, someone has to decide whether it leaks too much about the people in it. This chapter runs the attacks of this part together, as the assessment a privacy reviewer would ask for. It covers three typical releases: a classifier behind a scoring API, a language model whose weights go to a partner, and a record-level census extract.

The order of the work matters as much as the attacks. Before you run anything, you write down which results would block the release, because a threshold chosen after seeing the numbers can be bent to fit them. A failed attack shows only that this attack failed, so the assessment also reports how strong its attacks were.

Three scripts do the work on public data. practitioner_lira.py and practitioner_table_risk.py run in seconds. The language-model step reuses the output of practitioner_lora.py, the script of Fine-tune a language model privately with LoRA, which takes a few minutes on an idle CPU.

uv run python code/part02-attacks/practitioner_lira.py
uv run python code/part02-attacks/practitioner_table_risk.py
uv run python code/part05-dp-ml/practitioner_lora.py

18.2 Fix the threat model and the thresholds first

Start from the worksheet of Threat models and privacy games, which asks what the secret is, what the adversary observes and what it already knows. Answer it once per artefact, because the same data can be exposed differently in each release. The default privacy unit, what the assessment protects, is the person. The default adversary sees scores, the confidences a model returns, not just labels, since many services return them.

Then write the blocking rules into the plan, as in Table 18.1. The membership rule uses two rates. The true positive rate (TPR) is the share of members an attack flags, and the false positive rate (FPR) the share of non-members it wrongly flags. At an FPR of \(10^{-3}\), the rule blocks when the lower end of the TPR’s 95% confidence interval exceeds ten times the FPR, so a lucky run cannot trigger it. The factor of ten is a policy choice: an attack may beat chance, but not tenfold.

Several remedies in the table use differential privacy (DP), Part 3’s guarantee that caps what any attack can learn about one person by a privacy level \(\varepsilon\). One is stochastic gradient descent (SGD) with each record’s gradient clipped and noise added, called DP-SGD.

A smallest class of 5 is a common threshold, and US Medicare and Medicaid data in effect require 11, because their cell-size policy forbids publishing counts from 1 to 10. A canary within 3 bits of the maximum exposure ranks among the 8 likeliest of all possible secrets. The rule reads one-copy canaries because a deduplicated corpus holds each secret once. If yours is not deduplicated, apply it at your data’s largest repeat count.

The four middle rows block on any leak beyond the attack’s own baseline, which attribute, property and reconstruction attacks and gradient inversion each define. The last row is for a model trained with DP. An audit with independent trials certifies a lower bound on its \(\varepsilon\), and a bound above the claim proves a bug (Auditing private training).

18.3 Classifier: the free check

Compare the model’s accuracy on its training data with its accuracy on held-out data. Then run the loss attack, which says “member” whenever the loss on the true label is low (Membership inference). The model is a logistic regression on scikit-learn’s digits, 1,797 small images of handwritten digits. The script trains 64 copies, each on a random half of the images, because the next step uses them as shadow models. Every copy in turn plays the target, the model under assessment.

target 0: train accuracy=1.0000  test accuracy=0.9650
train-test gap, mean over 64 targets=0.0422
ART rule-based attack on target 0: TPR=1.0000  FPR=0.9650  advantage=0.0350
loss attack at FPR 0.001: TPR=0.0009
loss attack at FPR 0.01: TPR=0.0105

The first target gets every training image right, but only 0.9650 of its test images. So even “member if correctly classified” beats chance, by the mean gap of 0.0422, a free lower bound on the leak that does not say who is exposed. The Adversarial Robustness Toolbox (ART), a Python library of attacks, runs that rule as MembershipInferenceBlackBoxRuleBased, and on the first target its advantage of 0.0350 is that model’s gap. At an FPR of \(10^{-3}\) the loss attack flags no more members than non-members. A weak attack’s failure proves little, so this check can never clear a model. A large gap is reason enough to regularize first, while a small one only means you need the next step.

18.4 Classifier: LiRA with shadow models

The likelihood ratio attack (LiRA) compares the target’s output on a record with other models’ outputs on that same record. Shadow models are trained like the target on random halves of the data, so some trained on a given image and some did not. LiRA works with \(\phi = \ln(p/(1 - p))\), the logit of the confidence \(p\) in the true label, which is close to normal across retrainings. For each image, it fits a normal to \(\phi\) over the shadows that trained on it (IN) and another over those that did not (OUT). Online LiRA scores the target’s \(\phi\) by its log-likelihood ratio between the two fits. Offline LiRA uses only the OUT fit, and scores \(\phi\) by how many OUT standard deviations it lies above the OUT mean (Membership inference shows the code).

ART’s SklearnClassifier trains every model, but no library installed with this book computes the LiRA scores, so they come from the helper practitioner_privacy_tests.py.

Four decisions set the attack’s strength. Use online LiRA for a release decision, because it is the strongest. Train 64 shadows when training is cheap. With 16 or fewer, fit one variance shared by all images, because per-image variances from a handful of models are too noisy. Put each record in each model by a fair coin, so that every record has IN and OUT shadows. Finally, rotate the target role, so that each model serves once as the target with the other 63 as its shadows. Every model then judges every image, which gives 57,704 member and 57,304 non-member pairs of a model and an image.

An FPR of \(10^{-3}\) rests on few false positives, so the reading needs care. The script takes the best TPR among thresholds whose FPR stays at or below the target. It counts the true and false positives and puts a Clopper–Pearson interval, the exact binomial interval of Hypothesis testing, on each rate.

# Every (target model, image) pair is one trial; members are the positives.
fpr, tpr, thresholds = roc_curve(member.ravel(), scores.ravel())
# The best TPR among thresholds whose FPR does not exceed the target.
i = int(np.flatnonzero(fpr <= target_fpr)[-1])
n_members, n_nonmembers = int(member.sum()), int((~member).sum())
true_pos = round(tpr[i] * n_members)
false_pos = round(fpr[i] * n_nonmembers)
# Exact 95% intervals (Clopper-Pearson) for both rates.
tpr_ci = clopper_pearson(true_pos, n_members)
fpr_ci = clopper_pearson(false_pos, n_nonmembers)

  ART shadow-model attack: AUC=0.570  TPR@0.001=0.0014  TPR@0.01=0.0146
  LiRA offline: AUC=0.577  TPR@0.001=0.0087  TPR@0.01=0.0345

  ART shadow-model attack: TP=82/57704  TPR=0.0014 [0.0011, 0.0018]  FP=57/57304  FPR=0.00099 [0.00075, 0.00129]  ln(TPR/FPR)=0.36  pass

  LiRA online: TP=1833/57704  TPR=0.0318 [0.0303, 0.0332]  FP=57/57304  FPR=0.00099 [0.00075, 0.00129]  ln(TPR/FPR)=3.46  block

By area under the curve (AUC) the four attacks look alike, but at an FPR of \(10^{-3}\) they differ sharply. Online LiRA flags 1,833 members, a TPR of 0.0318. The lower end of its interval, 0.0303, is above 0.01, so the model fails Table 18.1. Offline LiRA would have passed it, and so would ART’s attack of Shokri et al. (2017), which learns one rule for all images from four shadow models of its own. That is why a release decision rests on the strongest attack you can afford. A model with privacy level \(\varepsilon\) keeps the TPR within about \(e^{\varepsilon}\) times the FPR, so ln(TPR/FPR) is a point estimate of the \(\varepsilon\) the attack implies. It is not a certified lower bound, because the pairs share models and so are not independent trials (Auditing private training).

The script also prints the ten images whose IN and OUT fits lie furthest apart, the records an attacker exposes first. The top one is image 1658, a 9, given a confidence of 0.812 by models trained on it and 0.003 by the others. Online LiRA flags it, at an FPR of \(10^{-3}\), in all 33 models that trained on it. Inspect such records, usually rare or mislabelled ones.

Three things go wrong here. First, shadows trained with another recipe describe another model and so weaken the attack. Second, too few non-members leave the FPR uncertain, and even here its interval runs from 0.00075 to 0.00129. Hypothesis testing says how many you need, and advises choosing thresholds on one split and measuring on another. The script does both on the same pairs, which flatters the attack slightly. Third, a confidence of 1 makes \(\phi\) infinite. Compute it from the logits, the model’s raw outputs. Clipping the confidence, which the script can afford on the digits, hides a confident model’s most exposed records (Membership inference).

18.5 Fine-tuned language model: canaries and extraction

A language model can repeat a secret word for word, which a membership test does not measure. So the assessment plants canaries, random secrets of a fixed format, and checks how well the trained model knows them (Memorization and training-data extraction). The run adapts Pythia-14m with low-rank adaptation (LoRA) to 1,024 sequences of Tiny Shakespeare, once without privacy and once with DP at \(\varepsilon = 8\) per sequence.

The canaries should look like the secrets you fear. Each one reads “the pin of”, a name such as Alice, and “is”, followed by five random digits, separated by spaces so that every possible secret is exactly five tokens. Three canaries are inserted once, and three others each 4, 16 and 64 times. Three controls are drawn the same way and never inserted. The canaries make up a quarter of the training set, far denser than secrets in real data. So even a model this small memorizes them, and the non-private model is a positive control, one known to leak.

Each canary is scored in two ways, with the functions shown in Fine-tune a language model privately with LoRA. Exposure ranks the secret among random secrets of the same format, by the summed log-probability of its five digit tokens, and turns the rank into bits, as \(\log_2\) of the number of candidates minus \(\log_2\) of the rank. Use the sum, since the mean loss that transformers returns ranks secrets of different token counts wrongly. Extraction gives the model the prefix, lets it write the likeliest token five times (greedy decoding), and checks whether it wrote the secret. Run it with the partner’s decoding settings.

non-private 1 copies: mean exposure 2.0 bits  extrapolated 2.0  extracted 0/3
non-private 4 copies: mean exposure 5.9 bits  extrapolated 5.7  extracted 0/3
non-private 16 copies: mean exposure 10.0 bits  extrapolated 13.0  extracted 0/3
non-private 64 copies: mean exposure 11.0 bits  extrapolated 16.3  extracted 3/3
non-private controls: mean exposure 1.4 bits  extrapolated 1.5  extracted 0/3

Ranking among 2,000 random candidates caps the measured exposure at 10.97 bits. The whole space of secrets allows 16.61, so the measured column can never reach the blocking line 3 bits below that maximum. The extrapolated column, an estimate rather than a measurement, fits a skew-normal distribution to the candidates’ scores and reads how far into its tail each secret lies. A never-seen secret has a random rank, worth \(\log_2 e = 1.44\) bits on average, and the controls’ 1.4 bits match it, so the measurement is sound. The one-copy canaries stay far below the blocking line, at 2.0 bits extrapolated on average. But greedy decoding writes out all three 64-copy secrets, so the non-private model fails Table 18.1 and must not be shared.

The 4-copy canaries show why you measure both. Two of them reach 6.9 and 8.2 bits, yet neither is extracted, so exposure finds memorization that extraction misses. The DP run extracts nothing, but its most repeated canaries still average about 4 bits, against 2.2 for its controls. That is because \(\varepsilon\) protects one sequence, and a repeated secret is many sequences. So deduplicate before training, whatever else you do.

The usual failures are a canary format unlike your data, no controls to show what chance looks like, and ranking by a mean loss over secrets of different lengths. The script also skips the discoverable rate, the share of training sequences whose start makes greedy decoding reproduce the rest. Add it for a release, as Memorization and training-data extraction describes.

18.6 Table: re-identification on quasi-identifiers

Quasi-identifiers are the columns an adversary can find elsewhere, such as age, sex and country in a register (Linkage and re-identification). Records that agree on all of them form an equivalence class, and a record alone in its class can be linked to a name.

The table is Adult, a census extract from the UCI Machine Learning Repository, with 48,842 records. The agreed set has six columns, from age to education, and the script adds hours worked per week to show what one more column does. For each set it prints the share of unique records and the share in classes smaller than 5. It also prints the smallest class size \(k\), and J/n, the number of classes per record, which nears 1 as records become unique. Linkage and re-identification shows the loop.

age + sex + race: unique=0.12%  in classes <5=0.75%  min k=1  J/n=0.012
age + sex + race + native-country: unique=3.07%  in classes <5=7.83%  min k=1  J/n=0.060
age + sex + race + native-country + marital-status + education: unique=14.64%  in classes <5=26.83%  min k=1  J/n=0.227
age + sex + race + native-country + marital-status + education + hours-per-week: unique=36.55%  in classes <5=57.05%  min k=1  J/n=0.480

On the agreed six, 14.64% of the records are unique, and hours per week, a column that looks harmless, raises that to 36.55%. The list must therefore include every column an adversary might hold, and when in doubt you test with the column added.

The standard remedy is to generalize. Age goes into 10-year bands, country into United States or other, and education into four levels. The script then checks the classes again and counts the distinct occupations in each, with occupation standing in for a sensitive column. That count is the distinct \(\ell\) of Syntactic anonymity and how it breaks, which shows the code.

after generalizing: unique=0.94%  in a class with one occupation=1.20%
age + sex + race + native-country + marital-status + education: unique=0.94%  in classes <5=3.31%  min k=1  J/n=0.032
age + sex + race + native-country + marital-status + education + hours-per-week: unique=10.09%  in classes <5=21.78%  min k=1  J/n=0.175

Generalizing cuts the unique share on the six from 14.64% to 0.94%, but the smallest class still has one record, so the table still fails Table 18.1. Suppressing the classes smaller than 5 would remove 3.31% of the records. The result would hold only for this list of columns, since adding raw hours per week makes 10.09% unique again. Generalizing also leaves 1.20% of the records in a class with a single occupation, which reveals it even without a unique match.

These figures count uniqueness in the sample, which fits the prosecutor model, where the adversary knows the target is in the table. Otherwise estimate population uniqueness (Linkage and re-identification).

Even a table that passes after suppression has two limits. A second release of the same people can be intersected with this one (Syntactic anonymity and how it breaks). And k-anonymity, which promises each class at least \(k\) records, says nothing against richer side information. So when a record-level table cannot pass without losing its use, release statistics with DP instead, as Release statistics with a library does. Published aggregates carry their own risk, since many overlapping counts let an attacker rebuild records (Reconstruction attacks).

18.7 Write the decision

The last step compares each result with its threshold and writes a release memo. A reviewer who did not run the attacks must be able to check it, so it gives each estimated rate with its interval, while counts on the table are exact. Table 18.2 fills it in for the three artefacts.

The residual-risk entry, most often left out, names the attacks that were not run. Write it even when every attack fails, because a model can pass this assessment and still leak to an attack nobody tried, and only a DP guarantee bounds every attack at once. For a DP model, the memo also carries the guarantee and its evidence, which Release and governance assembles into the release package.

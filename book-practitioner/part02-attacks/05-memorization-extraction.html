7  Memorization and training-data extraction

Author

Manuel V. Loureiro

Published

Version 2026-10-30

7.1 Why this matters

A language model trained on scraped text or support tickets sees phone numbers, addresses, keys and private messages. Asked to continue “Anna Smith’s phone number is”, it may finish with the real number. This is training-data extraction. Membership inference needs the record in hand to ask whether it was used, while extraction hands the attacker the record itself.

7.2 Which memorization to measure

The notions of memorization in Table 7.1 give rates that differ by orders of magnitude, so a report must say which one it measures. All use greedy decoding, which writes out the most likely next token at each step.

Discoverable memorization is the one you can measure, because you hold the training text it uses as the prompt. Treat any verbatim rate as a lower bound on the leak, because near copies leak too. A filter that blocks only verbatim training text is easy to bypass (Ippolito et al. 2023).

Deployed systems sample rather than decode greedily, so whether a string comes out depends on how many samples the attacker draws. A sample at temperature 1 writes out a string with probability \(p\), the model’s probability of that string after the prompt. Write \(\beta\) for the chance of failure the attacker accepts. Then a number \(m\) of independent samples suffices when \[m \ge \frac{\ln(1/\beta)}{p}. \tag{7.1}\] For a string of probability \(10^{-3}\) and \(\beta = 0.01\), that is about 4,600 samples. So report a sampling budget alongside the greedy rate, and measure with the decoding settings you deploy.

7.3 What gets memorized, and the first defences

Memorization grows with the copies of a string. On open models, the largest reproduced at least 1% of its training data in the discoverable sense (Carlini et al. 2023). A sequence repeated ten times is generated about a thousand times more often than one seen once (Kandpal, Wallace & Raffel 2022).

So the cheapest defence is deduplication, which lowers the copies of every repeated string. Models trained on deduplicated data emit memorized text about ten times less often, at the same quality (Lee et al. 2022). Deduplicate before you plant the canaries of the next section, so that only they carry known copy counts.

The second defence removes personal data before training. A detector of personally identifiable information (PII), such as Microsoft’s Presidio, finds names, phone numbers and similar fields so that you can mask them. But it misses whatever its patterns do not cover. Neither defence helps a secret seen once in a large model, where one copy is enough. Only fine-tuning with differential privacy, which limits how much any one training sequence can change the model, gives a guarantee for such singletons.

7.4 Auditing with canaries and exposure

Discoverable memorization is all or nothing, while an auditor wants a graded answer. Carlini et al. (2019) plant canaries, random secrets of a fixed format such as “my pin is” followed by five random digits. After training, you order all the values the secret could have taken from the most to the least likely under the model. The planted value’s rank in that order is the number of guesses an attacker needs if it tries them in turn.

Write \(\hat r\) for the planted value and \(|\mathcal R|\) for the number of values in the set \(\mathcal R\) it could have taken. The exposure is the number of bits of search the model saves an attacker, \[\mathrm{exposure}(\hat r) = \log_2|\mathcal R| - \log_2\operatorname{rank}(\hat r). \tag{7.2}\] Each bit halves the guesses the attacker needs. At rank 1 the exposure reaches its maximum, \(\log_2|\mathcal R|\), and the secret can be extracted. For five digits, \(10^5\) values, the maximum is 16.61 bits.

Exposure works as an audit because we know how it behaves when the model memorized nothing. The canary’s value is uniformly random, so a model that never saw it gives it a uniformly random rank. So for any threshold of \(t\) bits, \[\Pr\big[\mathrm{exposure}(\hat r) \ge t\big] \le 2^{-t}. \tag{7.3}\] So \(2^{-\text{exposure}}\) bounds the p-value, the chance that an uninserted canary would look at least this memorized. The same uniform rank gives an uninserted canary an average exposure of \(\log_2 e\), about 1.44 bits, which the controls should match.

To run the audit, draw canaries in the format of the secrets your data could contain. A format unlike your data measures only how the model treats unfamiliar text. Insert each canary a chosen number of times, from once to many, keep some never inserted as controls, and fine-tune as usual. Then score each canary’s value, and many random values of the same format, by the model’s log-probability after the prefix. The share of random values that score at least as high estimates the rank fraction, the rank divided by \(|\mathcal R|\). Minus its base-2 logarithm is the exposure.

Most audits go wrong at the scoring step. A candidate’s log-probability is the sum over its tokens, but the mean loss that Hugging Face models return divides that sum by the number of tokens. Values of different token lengths then get scores on different scales, and the ranking is wrong. So score every candidate by its summed log-probability, in a format where every candidate has the same number of tokens. For example, write a pin as “the pin of Alice is 8 6 5 2 3”, so that each digit is one token.

Fine-tune a language model privately with LoRA runs this audit on Pythia-14m, a small language model, and shows the code and its output. It inserts three canaries at each copy count from 1 to 64 into 1,024 sequences of Tiny Shakespeare. It keeps three more as controls and ranks each value among 2,000 random candidates. Exposure rises with the copies, and the controls sit at 1.4 bits, as the 1.44 expected for them predicts. Greedy decoding extracts only the three canaries seen 64 times. Yet two of the canaries seen 4 times reach 6.9 and 8.2 bits, which no extraction test notices. So an audit measures exposure and not only extraction.

The 2,000 candidates set a cap on the measured exposure. A canary that beats all of them shows only that its rank fraction is below about 1 in 2,000. So its exposure stops at \(\log_2 2000 = 10.97\) bits. Past the cap, fit a skew-normal distribution to the candidates’ scores and read the canary’s rank off its tail, as Carlini et al. (2019) do. Ties also hide memorization, because when every candidate gets the same score, every exposure is 0.

A canary repeated 16 or more times is the positive control. If it does not reach a high exposure without privacy, the run is too short to tell you anything. In that run the canaries fill a quarter of the training set, which lets so small a model memorize them. Pre-release privacy risk assessment sets the exposure that blocks a release.

7.5 Extraction without the prefix: generate, rank, verify

A real attacker has only the model. Carlini et al. (2021) extracted data from GPT-2 in three steps. They generated many samples, ranked them by how likely each was to be memorized, and checked the top ones. The ranking is the hard step, because a model finds a string likely either because it is ordinary text or because it memorized it. A reference model, trained on similar data but not on the target’s training set, stands in for ordinary text. Write \(p_\theta(x)\) for the target model’s probability of a string \(x\), and \(p_{\mathrm{ref}}(x)\) for the reference’s. Rank by the log-likelihood ratio \[\Lambda(x) = \ln p_\theta(x) - \ln p_{\mathrm{ref}}(x). \tag{7.4}\]

The ratio cancels the strings that any model finds likely, such as software licences and boilerplate. Raw likelihood would put these first, and they reveal nothing. A crude reference, such as a smaller model of the same family, works. To audit your own fine-tuned model, use the base model as the reference.

Without the prefix, an attacker extracts less than the discoverable rate suggests, but aligned production models are not safe. Nasr et al. (2023) asked ChatGPT to repeat one word forever, until it left its aligned behaviour and wrote memorized text. For about 200 US dollars of queries, they extracted over 10,000 records.

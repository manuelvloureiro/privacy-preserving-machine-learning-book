# Privacy accounting

The [previous part](../part03-dp-foundations/00-introduction.md) defined differential privacy (DP), built the basic mechanisms and showed how $(\varepsilon, \delta)$ guarantees add up when mechanisms run one after another. That is enough for a handful of releases, not for training a model, which runs thousands of noisy steps, each on a random subset of the data, and must then state one $\varepsilon$. No single theorem gives that number. It comes from an **accountant**, a procedure that tracks a summary of each step's privacy loss, combines the summaries, and converts the result into the $(\varepsilon, \delta)$ you report. Two accountants given the same training run can report values of $\varepsilon$ that differ by a large factor, and both can be correct upper bounds; only the tighter one tells you what the noise bought.

Read this part if you train models with DP, or review or audit a model that claims an $\varepsilon$. It assumes [Differential privacy foundations](../part03-dp-foundations/00-introduction.md): the definition, the privacy loss of an output, the Gaussian mechanism and its exact curve $\delta(\varepsilon)$, and composition. Each chapter restates in a sentence what it uses.

## The common thread

The privacy loss of an output is the log of how much more likely that output is with your record than without it. Over a run, the per-step losses add, so for the loss itself composition is easy. For $(\varepsilon, \delta)$ it is hard, because a pair of numbers is one point of a whole curve and forgets almost everything about how the loss is distributed. Composing points pays for that lost information at every step. Every accountant in this part makes the same move instead: **track a richer summary of the privacy loss, one that composes simply, and convert to $(\varepsilon, \delta)$ only once, at the end.**

The chapters differ in the summary they keep, and their order follows from it. The first two introduce Rényi differential privacy (RDP), the summary most libraries use: a curve of exponential moments of the loss that adds up step by step, and the conversion that turns the final curve into the reported pair. Every later chapter starts from that curve, so they come first. Concentrated DP then squeezes the curve into one number $\rho$, which describes Gaussian noise exactly and many other mechanisms only loosely, and f-DP goes the other way, keeping the whole trade-off between an attacker's false positives and missed detections, which reads directly as attack power.

None of these summaries yet explains why training is private at all. The differentially private version of stochastic gradient descent (SGD), DP-SGD, clips each example's gradient and adds Gaussian noise, and if every step used the whole dataset its guarantee would be useless. It is private because each step touches a random fraction of the records, so most steps don't see a given record at all. Amplification by subsampling turns that into a much smaller per-step loss. It is a separate question from the summary, since it decides which pair of output distributions you account for, and it must match how the training code really samples its data. Numerical accounting then keeps the whole distribution of the loss and composes it with a discretization error it bounds, which makes it the tool that checks every other accountant. These two chapters are the practical core, in that order, because the numerical accountant takes the subsampled step as its input.

The last chapters handle departures from that setting. Shuffling instead of sampling, or releasing only the final model, can give extra privacy, but only under assumptions the code has to meet. Budgets chosen while training runs, or privacy spent differently per record, break the assumption that each step's bound is fixed in advance, and need filters and odometers. The final chapter puts the pieces together.

## The running example

Every chapter that can compute it reports the same number: the $\varepsilon$ at $\delta = 10^{-5}$ of DP-SGD with Poisson sampling rate $q = 0.01$, noise multiplier $\sigma = 1$ and up to $k = 10{,}000$ steps. That is about one hundred epochs at a typical setting. A single Gaussian mechanism with $\sigma = 1$ serves as the small example. Watching the same number move from chapter to chapter shows what each tool gains, and [Choosing an accountant](09-choosing-an-accountant.md) puts all the values side by side.

## What you will be able to do

By the end of this part you will be able to compute the RDP curve of a Gaussian training step, compose a run of them and convert the result with the right conversion. You will know what each summary keeps and loses, how much subsampling buys and which sampling scheme it assumes, and how to check any accountant against a numerical one. And for a DP-SGD run you will be able to pick an accountant, state its assumptions, and report $\varepsilon$ in a way someone else can check.

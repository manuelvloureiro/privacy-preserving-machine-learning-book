# Privacy accounting

A model trained with stochastic gradient descent (SGD) under differential privacy (DP), the method called DP-SGD, takes thousands of noisy steps, each on a random batch. The guarantee you report is a privacy level $\varepsilon$ with a small slack $\delta$, the chance that the promise fails for a person ([Numerical accounting](06-numerical-accounting.md) defines it exactly). The composition theorems of Part 3 are far too loose for thousands of steps. An **accountant** does better, because it tracks a richer summary of each step's privacy cost that composes tightly, and converts the total to $(\varepsilon, \delta)$ once, at the end.

One DP-SGD run is the running example. Each step samples each example with probability 0.01 and adds noise with multiplier 1. After 10,000 steps, advanced composition certifies $\varepsilon = 24{,}379.55$ at $\delta = 10^{-5}$. But a privacy loss distribution accountant certifies only 6.24 for the same run ([Choosing an accountant](09-choosing-an-accountant.md)). So an $\varepsilon$ means nothing until you name the accountant that produced it, which is also why libraries and papers can disagree about the same run.

If you train with DP-SGD, read four chapters. [Rényi differential privacy](01-renyi-dp.md) is the curve that most accountants track. [Amplification by subsampling](05-subsampling.md) shows how much a random batch helps, provided the data loader samples the way the accountant assumes. [Numerical accounting with privacy loss distributions](06-numerical-accounting.md) computes the tightest $\varepsilon$ available, and [Choosing an accountant](09-choosing-an-accountant.md) turns the part into a decision guide.

The other chapters serve narrower needs. [From Rényi DP to (ε, δ) and to tests](02-rdp-conversions.md) explains the conversion behind every Rényi number. [Concentrated differential privacy](03-concentrated-dp.md) budgets analytics queries with one number. [f-DP and Gaussian differential privacy](04-gaussian-dp.md) reads a guarantee as a limit on attacks. [Amplification by shuffling and by iteration](07-shuffling-iteration.md) and [Adaptive composition](08-adaptive-composition.md) cover shuffled pipelines and budgets decided during training.

The part uses the accountants of three libraries, Opacus, Google's `dp_accounting` and Microsoft's `prv_accountant`. Each chapter ends with a link to the full edition, which derives every result.

By the end, you will be able to account for a DP-SGD run with a library and check it against a second one. Above all, you will report $\varepsilon$ with the accountant that produced it, so that someone else can reproduce it.

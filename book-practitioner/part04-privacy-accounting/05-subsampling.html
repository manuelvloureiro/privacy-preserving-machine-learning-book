33  Amplification by subsampling

33.1 Why this matters

Most private models are trained with stochastic gradient descent (SGD) made to satisfy differential privacy (DP), a method called DP-SGD. Each step clips every example’s gradient, sums the clipped gradients and adds Gaussian noise, whose standard deviation is the clipping norm times the noise multiplier \(\sigma\). Suppose every record paid the full cost of a Gaussian mechanism at every step. With \(\sigma = 1\), ten thousand steps would then cost a privacy level of \(\varepsilon = 5425.5\) (Rényi DP).

DP-SGD escapes this cost because each step looks only at a small random batch. Write \(q\) for the sampling rate, the probability that a given record lands in the batch. An attacker must then first guess whether the record was used at all, and that uncertainty is worth a lot. This effect is called amplification by subsampling. It depends on exactly how the batch was drawn, so the accountant, the code that adds up a run’s privacy cost, must assume the sampler the training code actually runs. Getting that wrong is the largest single error in DP-SGD accounting.

33.2 One step under Poisson sampling

The simplest sampler is Poisson sampling, in which each record enters the batch by its own coin flip, with probability \(q\), independently of every other record. Pair it with add/remove neighbours, datasets that differ by one record being present or absent. Balle, Barthe and Gaboardi (2018) give the tight result. If a step is \((\varepsilon, \delta)\)-DP on its own, where \(\delta\) is the slack, then the same step run on a Poisson sample is \((\varepsilon', \delta')\)-DP with \[\varepsilon' = \ln\big(1 + q(e^\varepsilon - 1)\big), \qquad \delta' = q\delta. \tag{33.1}\]

The formula behaves very differently for small and large \(\varepsilon\). For small \(\varepsilon\) the amplified cost is about \(q\varepsilon\), so a 1% sample makes a step about a hundred times cheaper. With that sample, for example, a 1-DP step costs 0.0170. But for large \(\varepsilon\) the amplified cost is about \[\varepsilon' \approx \varepsilon - \ln(1/q), \tag{33.2}\] so sampling only subtracts a fixed amount. With the same sample, a 10-DP step still costs 5.3993. The switch happens where \(\varepsilon\) is near \(\ln(1/q)\).

The result has two conditions. Each record’s coin must be independent of the others, so that the record is drawn with probability exactly \(q\) whatever else is in the batch. And the batch must stay secret, because an attacker who sees the list of records drawn knows whether the target was used. The rule applies to any \((\varepsilon, \delta)\)-DP step, not only to the Gaussian. So a pure DP or randomized-response release run on a secret Poisson sample is amplified too. For example, 1-DP randomized response on a 10% sample costs 0.1586. Per-step pairs compose badly over thousands of steps, though (Section 33.4).

33.3 Match the sampler to the accountant

Most training code does not draw Poisson batches. Some draws a fresh random batch of a fixed size, written \(m\), from the \(n\) records at each step. Much more code shuffles the data once per epoch and cuts the list into consecutive batches, which is called shuffle and partition. Each sampler pairs naturally with a neighbouring relation, and Table 33.1 gives what to account for under each pairing.

The factor of two in the noise comes from the gradient sum. Adding or removing a record moves the clipped sum by at most the clipping norm. But a record that enters a fixed-size batch pushes another one out, so the sum can move by twice as much. Twice the shift with the same noise is the same as the original shift with half the noise multiplier, and that is not a small change. This part’s running example takes ten thousand steps with \(q = 0.01\) and \(\sigma = 1\). At \(\delta = 10^{-5}\), the Poisson accountant gives it \(\varepsilon = 6.71\). With fixed-size batches under add/remove it must be run at \(\sigma = 0.5\), and it then gives 47.42, about seven times more.

Shuffle and partition is worse, because the source of amplification is missing. Within an epoch the record is in exactly one batch and is never absent, so the attacker only has to find which batch held it. Chua et al. (2024) build a dataset where the target’s batch stands out, under zero-out neighbours, which set the target’s gradient to 0. A test on it proves that one shuffled epoch of the running example has \(\varepsilon\) of at least 4.06, while a Poisson accountant reports at most 1.21. So a Poisson number reported for shuffled training can be provably false.

So read the data loader before you trust a reported \(\varepsilon\). A PyTorch DataLoader with shuffle=True and a batch_size is shuffle and partition, and a tf.data pipeline that shuffles and then batches is not Poisson sampling either. Opacus replaces the loader with a Poisson one by default: PrivacyEngine.make_private takes poisson_sampling=True unless you turn it off, and opacus.data_loader.DPDataLoader.from_data_loader converts a loader by hand. A Poisson loader gives batches of varying size, which is a quick check that it is in use. When the largest batches do not fit in memory, Opacus’s BatchMemoryManager splits them into physical batches without changing the accounting (Private stochastic gradient descent). If you cannot use Poisson sampling, report under the matching row of Table 33.1, or say plainly that \(\varepsilon\) assumes a sampler you did not run.

33.4 The accountant for DP-SGD

Accountants for DP-SGD work in Rényi differential privacy (RDP), which describes a mechanism by a curve \(\varepsilon(\alpha)\) over orders \(\alpha > 1\) (Rényi DP). Curves add over steps, even adaptive ones. So a run of \(k\) steps has the curve \(k\,\varepsilon(\alpha)\), which is converted to \((\varepsilon, \delta)\) once.

Mironov, Talwar and Zhang (2019) show that one Poisson-subsampled Gaussian step has, at integer orders, the curve \[\varepsilon(\alpha) = \frac{\ln A_\alpha}{\alpha - 1}, \qquad A_\alpha = \sum_{j=0}^\alpha\binom\alpha j(1 - q)^{\alpha - j}q^j\exp\Big(\frac{j^2 - j}{2\sigma^2}\Big). \tag{33.3}\] Here the index \(j\) counts the imagined copies of the run that used the record, and accountants compute fractional orders by numerical integration. On the running example the curve is tiny at low orders. At order 2, for example, it is \(1.7181 \times 10^{-4}\), against 1 without sampling. Table 33.2 shows what the accountant gives over a run, against the per-step route that amplifies each step with Equation 33.1 and then composes the pairs.

The per-step route fails because each step keeps a tiny share of \(\delta\), which forces a large per-step \(\varepsilon\) that sampling barely reduces. So never compose per-step pairs for DP-SGD. The best order also falls as the run grows, to about 4 at ten thousand steps. So make sure the accountant’s grid includes small and fractional orders, because a missing order can only raise \(\varepsilon\).

In practice you use a library. Opacus’s RDPAccountant and Google’s dp_accounting.rdp.RdpAccountant both compute Equation 33.3, and in dp_accounting you describe a step as PoissonSampledDpEvent(sampling_probability, GaussianDpEvent(noise_multiplier)). For fixed-size batches it has a SampledWithoutReplacementDpEvent for the replace-one relation, while Microsoft’s prv_accountant describes the same step as a PoissonSubsampledGaussianMechanism. The value 6.71 is still an upper bound, and numerical accounting computes the tight value.

33.5 Small q and the design of a run

For small \(q\) the curve has a simple leading term, which is what makes the trade-offs between batch size, noise and epochs visible: \[\varepsilon(\alpha) \approx \frac{\alpha q^2\big(e^{1/\sigma^2} - 1\big)}{2} \approx \frac{\alpha q^2}{2\sigma^2}\ \text{for large } \sigma. \tag{33.4}\] The per-step cost is quadratic in \(q\), while a run of \(E\) epochs takes \(E/q\) steps. So the total RDP is about \[\frac{E\,q\,\alpha}{2\sigma^2}. \tag{33.5}\] At a fixed number of epochs, smaller batches are therefore cheaper in privacy.

That gives the recipe for planning a run. Fix the batch size \(B\) and the number of epochs \(E\) that your accuracy needs. Then the sampling rate is \(q = B/n\) and the number of steps is \(k = En/B\), where \(n\) is the size of the dataset you actually train on, after any filtering. A wrong \(n\) gives a wrong \(q\), and so a wrong \(\varepsilon\). Let the accountant solve for the noise multiplier that meets the target. Opacus does this with get_noise_multiplier(target_epsilon=..., target_delta=..., sample_rate=..., epochs=...), or in one call with make_private_with_epsilon. Then check the result with a second accountant (Choosing an accountant).

Use Equation 33.4 for planning only, never inside an accountant, because at high orders it is far too small. The closed-form bound of the original moments accountant (Abadi et al. 2016) has the same shape and is outdated.

33.6 Other mechanisms

For RDP, unlike for Equation 33.1, no rule returns every mechanism’s subsampled curve exactly. General bounds for other mechanisms exist (Zhu & Wang 2019), but they are looser, so use the exact sum for the Gaussian.

33.7 Code

The accountant below handles Poisson sampling and add/remove neighbours. It computes Equation 33.3 in log space at integer orders only, so its value for the running example is a little above the 6.71 of fractional orders.

from math import exp, lgamma, log


def subsampled_gaussian_rdp(alpha: int, q: float, sigma: float) -> float:
    """RDP at integer order alpha of one Poisson-subsampled Gaussian step (sensitivity 1)."""
    logs = [
        lgamma(alpha + 1) - lgamma(j + 1) - lgamma(alpha - j + 1)
        + (alpha - j) * log(1 - q) + j * log(q) + (j * j - j) / (2 * sigma**2)
        for j in range(alpha + 1)
    ]
    top = max(logs)
    log_a = top + log(sum(exp(t - top) for t in logs))  # log-sum-exp avoids overflow
    return log_a / (alpha - 1)


def dpsgd_eps(q: float, sigma: float, steps: int, delta: float) -> tuple[float, int]:
    """Compose over the steps, convert with the improved conversion at the best integer order."""
    best = (float("inf"), 0)
    for alpha in range(2, 64):
        rdp = steps * subsampled_gaussian_rdp(alpha, q, sigma)
        eps = rdp + log((alpha - 1) / alpha) - (log(delta) + log(alpha)) / (alpha - 1)
        best = min(best, (eps, alpha))
    return best


print(f"{subsampled_gaussian_rdp(2, 0.01, 1.0):.4e}")  # 1.7181e-04
print("%.3f %d" % dpsgd_eps(0.01, 1.0, 10_000, 1e-5))  # 6.719 4

33.8 Cheat sheet

Rules of thumb

  • Account for the sampler you run, and state the neighbouring relation next to \(\varepsilon\).
  • The sampler can move \(\varepsilon\) by a factor of seven, while the choice of conversion moves it by about 10%.
  • Never compose per-step \((\varepsilon, \delta)\) pairs for DP-SGD. Compose RDP curves or privacy loss distributions, and convert once.
  • Keep the small-\(q\) formula for planning, never for the reported number.
  • Compute \(q\) from the dataset you actually train on, after filtering.
  • A Poisson add/remove number does not hold for a replace-one claim.

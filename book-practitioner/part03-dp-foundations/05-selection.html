23  Selection: exponential mechanism, report-noisy-max, sparse vector

23.1 Why this matters

Many questions ask you to pick something, such as the best model on a validation set, a median, or the first alarm among many statistics. If you publish the score of every candidate with Laplace noise, you pay the budget once per candidate, because the budgets of separate releases add. The mechanisms of this chapter release the position, not the values. One record can change the winner only a little, for any number of candidates. So under differential privacy (DP), a selection costs as much as a single query, and the number of candidates changes only the accuracy, through its logarithm.

23.2 Which mechanism to use

Table 23.1 gives the mechanism for each common task. In each, the sensitivity \(\Delta u\) is the most that one person’s record can change the score of a candidate.

23.3 The exponential mechanism

The candidates form a fixed set, written \(\mathcal R\). Each candidate \(r\) has a score on the dataset \(D\), written \(u(D, r)\), such as the number of validation records that a model gets right. The exponential mechanism of McSherry and Talwar (2007) picks each candidate with a probability proportional to an exponential of its score. With a privacy budget \(\varepsilon\), it outputs candidate \(r\) with probability \[\Pr[M_E(D) = r] = \frac{\exp\big(\varepsilon\,u(D, r)/(2\Delta u)\big)}{\sum_s\exp\big(\varepsilon\,u(D, s)/(2\Delta u)\big)}. \tag{23.1}\] It is \(\varepsilon\)-DP because one record changes each weight, and also their sum, by at most a factor \(e^{\varepsilon/2}\), which makes \(e^\varepsilon\) for their ratio.

Two conditions decide whether a use is correct. First, fix the list of candidates before you look at the data. A list made from the data reveals records by itself, such as a word that only one person used. Second, remove the 2 in the exponent only when the scores are monotone, which means that one record pushes all of them the same way. Counts under add/remove neighbours are monotone. A histogram under replace neighbours is not, because a moved record lowers one count and raises another, so without the 2 the cost is double.

23.4 Accuracy, and the cost of many candidates

The number of candidates \(|\mathcal R|\) costs no privacy but costs accuracy, because more candidates means more bad ones to pick. Call the best score minus the score of the chosen candidate the gap. On average it is at most \[\frac{2\Delta u}{\varepsilon}(\ln|\mathcal R| + 1), \tag{23.2}\] so twice the candidates add only \(\ln 2\) to the bracket.

Suppose that you trained 50 models and want to release the best one on a private validation set of 1,000 records. Model \(r\), numbered from 1, gets \(900 - r\) records right, so model 1 is the best. The score is that count, which one record moves by at most 1, so \(\Delta u = 1\). At \(\varepsilon = 1\), the mechanism picks the best model only 39% of the time. But it loses only 1.54 correct predictions on average, or 0.15% accuracy, because its mistakes are mostly near-ties. Hyperparameter tuning picks models this way.

23.5 A private quantile or clipping norm

A median or a clipping norm read from the data leaks the data, so pick it with the exponential mechanism. Before you look at the data, fix a range. Then clip every record into it. The score of each point of the range is how close the share of records below it is to the quantile that you want. For the median, that quantile is one half. One added or removed record moves each score by at most 1. The score stays the same between consecutive sorted records, so the mechanism picks one of these intervals, called pieces, and returns a uniform point inside it. It prefers long pieces near the quantile.

diffprivlib’s tools.quantile and tools.median take an epsilon and the range as bounds. OpenDP’s .dp.quantile and .dp.median work on Polars data frames and pick one value from a finite list of candidates. The script practitioner_adult_statistics.py takes the median age of the Adult census data, 48,842 people with one row each, at \(\varepsilon = 1\). The range of 17 to 90 comes from the survey’s documentation.

age = adult["age"].to_numpy()
private = tools.median(age, epsilon=1.0, bounds=(17, 90), random_state=seed)
print(f"true median age: {np.median(age):.1f}  diffprivlib median: {private:.2f}")

With random_state=0, it prints a true median of 37.0 and a private one of 37.72. Ages are whole numbers, so every point between 37 and 38 has the same score, and the mechanism picked a random point in that piece. OpenDP does not run the median without a public upper bound on the number of rows, declared as a Margin. Choose a large bound from public facts, because it must be at least the true number of rows, and a larger bound costs almost nothing.

context = dp.Context.compositor(
    data=adult.lazy(),
    privacy_unit=dp.unit_of(contributions=1),  # one row per person
    privacy_loss=dp.loss_of(epsilon=1.0),
    split_evenly_over=1,
    margins=[dp.polars.Margin(max_length=100_000)],  # a public bound on the number of rows
)
age_col: Any = pl.col("age")  # OpenDP adds .dp to Polars expressions when it is imported
query = context.query().select(age_col.dp.median(candidates=list(range(17, 91))))
print(query.summarize(alpha=0.05))
released = query.release().collect()  # changes on every run: OpenDP's noise has no seed

Its summary shows ExponentialMin with a scale of 2.0, because OpenDP 0.16 adds exponential noise to the score of every candidate and reports the best. That is permute-and-flip (McKenna & Sheldon 2020), which has the guarantee of the exponential mechanism and never a worse error on average. The accuracy is null, because OpenDP gives no error bar for a quantile. The noise has no seed, so the released value changes on each run of uv run python code/part03-dp-foundations/practitioner_adult_statistics.py.

The error bar that you can state is about rank, not value. With probability \(1 - \beta\), the gap of the exponential mechanism is at most \((2\Delta u/\varepsilon)(\ln|\mathcal R| + \ln(1/\beta))\), the tail form of Equation 23.2. For a median, with \(\Delta u = 1\), the gap is the number of records by which the output misses the middle rank. So \(\beta = 0.05\) gives its 95% bar in ranks. A bar in value would need the number of records near the median, which the release does not show. If a dashboard needs values, spend budget on a few noisy counts below candidate values. A large range costs little, because its width changes the gap only through the logarithm of the number of candidates.

Two things go wrong in practice. Where the data near the quantile are sparse, the best piece is long and the output can be anywhere in it. Then a small error in rank is a large error in value. And the range or the candidates must not come from the data. For example, an upper end set to the observed maximum brings back the leak. diffprivlib warns with a PrivacyLeakWarning when you leave out bounds (Sensitivity).

23.6 Report-noisy-max and Gumbel noise

Report-noisy-max adds independent Laplace noise to the score of each candidate and outputs the candidate with the largest noisy score. It is \(\varepsilon\)-DP for any number of candidates when the noise has scale \(2\Delta u/\varepsilon\), or \(\Delta u/\varepsilon\) when one record pushes all scores the same way. Release only the index of the winner, and pay for a fresh noisy answer if you need its score.

Gumbel noise of scale \(2\Delta u/\varepsilon\) in place of the Laplace noise gives exactly the exponential mechanism. Libraries sample it with this Gumbel-max trick, because the exponential of a score in the thousands overflows, but noisy scores do not. The \(c\) largest scores with Gumbel noise give the top \(c\) at once (Durfee & Rogers 2019).

23.7 The sparse vector technique

Sometimes queries come one at a time, and you want the first one that is high enough. The sparse vector technique (Dwork et al. 2009) compares each query with one noisy threshold and pays only for the query that fires. Its basic form, AboveThreshold, takes a threshold \(\tau\) and a stream of queries \(f\), all with the same sensitivity \(\Delta f\). It divides the budget into \(\varepsilon_1\) for the threshold and \(\varepsilon_2\) for the queries.

  1. Draw one threshold noise, written \(\nu\), from \(\mathrm{Lap}(\Delta f/\varepsilon_1)\) for the whole run.
  2. For each query, draw a fresh noise from \(\mathrm{Lap}(2\Delta f/\varepsilon_2)\) and add it to the answer of the query. If the result is at least \(\tau + \nu\), output “above” and stop. If not, output “below” and continue.

AboveThreshold is \((\varepsilon_1 + \varepsilon_2)\)-DP for any number of “below” answers, even when each query is chosen after the earlier answers. All the “below” answers together pay \(\varepsilon_1\), through the one threshold noise, and the single “above” pays \(\varepsilon_2\).

But the accuracy depends on the stream length \(k\), which you must fix before the run. Write \(\beta\) for the chance that the accuracy guarantee fails. With an equal split, \(\varepsilon_1 = \varepsilon_2 = \varepsilon/2\), every query gets the correct answer unless its true value is within a margin \[\alpha = \frac{8\Delta f\big(\ln k + \ln(2/\beta)\big)}{\varepsilon} \tag{23.3}\] of the threshold. Monitor 1,000 counts, each with \(\Delta f = 1\), against a threshold of 500 at \(\varepsilon = 1\). At \(\beta = 0.05\), the margin is 84.77. So with probability 0.95, only a count that near the threshold can get the wrong answer.

To find the first \(c\) queries above the threshold, start AboveThreshold again after each “above”, with fresh threshold noise and \(\varepsilon/c\) per run. Stop after the \(c\)-th. The margin then grows with \(c\), so ask for as few alarms as you can. Lyu, Su and Li keep one threshold for all \(c\) alarms and multiply the query noise by \(c\).

23.8 When the sparse vector technique goes wrong

Several published variants do not have the privacy they claim (Table 23.2).

The variant that never stops is the one to remember. It adds exactly as much noise per query as AboveThreshold, so a reviewer who checks noise scales does not find it. But at \(\varepsilon = 1\), its privacy loss gets to 18.1246 on 80 queries.

So review the accounting, not only the noise. Draw one threshold noise per run. If you draw the threshold again for each query, every “below” answer costs budget that nobody counted. Draw fresh noise for every query, because one noise draw for all of them is the same as Algorithm 5. Stop after the permitted number of “above” answers. Never publish the noisy values that you compared.

23.9 Cheat sheet

Rules of thumb

  • Release positions, not values.
  • Fix the candidate list, and the range of any number you pick, before you look at the data.

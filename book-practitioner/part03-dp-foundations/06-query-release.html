18  Query release and private multiplicative weights

18.1 Why this matters

Analysts ask for every two-way table over a few columns, or for a synthetic file to query as often as they like. Both must satisfy differential privacy (DP). Such tables are marginal tables. Each one counts the records for each combination of values of a few attributes, and each count is a cell.

These releases add noise to whole tables, not to single cells, and scale it to how much one person can change the table. One person is in one cell of a table, so a whole table costs about as much as one count. All later computation on the noisy tables is free. When the queries are too many for noise on every cell, use synthetic data fitted to a few noisy tables.

18.2 Which method to use

The choice depends on how many queries you have, compared with the number of records, and on the number of attributes of a record (Table 18.1).

One person is in every table, so the tables form a dense query, and the dense-query rule of the Laplace and Gaussian mechanisms tells where “a few” tables end. At a privacy level \(\varepsilon\) of 1 and a slack \(\delta\) of \(10^{-5}\), Gaussian noise is better from 7 tables on.

18.3 Noise on every cell

Under add/remove neighbours, a person with one record changes one cell of a marginal table by 1, so the whole table has sensitivity 1. Laplace noise of scale \(1/\varepsilon\) on every cell then makes the table \(\varepsilon\)-DP, by parallel composition. Under replace neighbours, a person can move from one cell to another, so two cells change and the sensitivity doubles.

Several tables of the same people compose. With Laplace noise, you split the budget among the tables, so the error per cell grows in proportion to their number. Gaussian noise scales with the square root of the sum of squared changes. For one person in a number \(m\) of tables, that is \(\sqrt m\), so the Gaussian error grows only like \(\sqrt m\).

For example, a table of 10,000 records has eight yes/no attributes, so \(2^8 = 256\) possible records. The release is every cell of the marginal table of every set of attributes, 6,560 cells in all. Each cell is a fraction of the records, under replace neighbours. A uniform guess, which ignores the data, has a largest error of 0.232 on these cells. At \(\varepsilon = 1\), Laplace noise on every cell is worse, with 0.497. Gaussian noise at \(\delta = 10^{-6}\) is much better, with 0.037.

Two mistakes are common. If you scale the noise of each cell to its own sensitivity, as if it were the only query, you silently spend \(\varepsilon\) once per table. And basic composition over thousands of separate cells wastes most of the budget. Calibrate to the whole set of tables instead.

18.4 Releasing a marginal with OpenDP

The script practitioner_adult_statistics.py releases the education-by-income table of the Adult census data, 48,842 people with one row each, at \(\varepsilon = 1\). The survey’s documentation lists 16 levels of education and two income classes, so the keys are public and the table has 32 cells. The release includes empty cells too, because a missing cell would show that nobody has those values. Map a missing value to a listed key such as “Unknown”, because OpenDP drops a row whose key is not in the list. In OpenDP, a Margin (a setting, not a marginal table) with invariant="keys" makes the list of cells public, and with_keys limits the release to exactly those cells.

keys = pl.LazyFrame({"education": EDUCATION}).join(pl.LazyFrame({"income": INCOME}), how="cross")
context = dp.Context.compositor(
    data=adult.lazy(),
    privacy_unit=dp.unit_of(contributions=1),
    privacy_loss=dp.loss_of(epsilon=1.0),
    split_evenly_over=1,
    margins=[dp.polars.Margin(by=["education", "income"], invariant="keys")],  # the cells are public
)
query = context.query().group_by("education", "income").agg(dp.len(signed=True)).with_keys(keys)
print(query.summarize(alpha=0.05))
released = query.release().collect()  # all 32 cells, zeros included; changes on every run

Run it with uv run python code/part03-dp-foundations/practitioner_adult_statistics.py. The summary is deterministic.

Each cell gets integer Laplace noise of scale 1 (Discrete and floating-point-safe mechanisms). The 95% accuracy of 3.38 means that each noisy count is that close to the truth 95% of the time. Print that error bar next to every cell, and note that it covers only the noise, not sampling error or mistakes in the data. OpenDP’s noise has no seed, so these four cells come from one run, next to the true counts.

  HS-grad <=50K: 13281  true 13281  accuracy 3.38
  Preschool <=50K: 82  true 82  accuracy 3.38
  Preschool >50K: 0  true 1  accuracy 3.38

The large cells barely move, but the smallest true cell, one person with a preschool education and a high income, is smaller than the noise. So if small cells matter, merge rare categories in advance. With signed=True, a count can come out negative, which keeps it unbiased. A clamp at zero, rounding, and scaling the cells to a total already released are post-processing, so they cost nothing.

Three things go wrong. First, a list of cells from the data, such as unique() on a private column, shows rare values by itself. Without a codebook, use partition selection (Release statistics with a library). Second, each extra table of the same people needs its own share of the budget, so set split_evenly_over to the number of tables. Third, for many tables, give the budget as dp.loss_of(rho=...), with the \(\rho\) that converts to your \((\varepsilon, \delta)\) (Release statistics with a library shows how). OpenDP then uses Gaussian noise, which composes far better, and accounts in zero-concentrated differential privacy (zCDP) (Concentrated differential privacy).

18.5 Synthetic data

When the queries are too many for noise on every cell, or nobody knows them in advance, release synthetic data, in four steps.

  1. Select a set of marginal tables to measure, from domain knowledge or privately with the exponential mechanism, scoring each table by how badly the current model fits it.
  2. Measure each whole table with Gaussian noise, scaled to the whole set.
  3. Generate a compact graphical model that fits the noisy tables.
  4. Sample synthetic rows from the model.

All steps after the measurements are post-processing. So you can query and share the synthetic rows at no more privacy cost. The standard methods are MST and AIM, by McKenna and coauthors, and AIM selects the tables to measure as it goes. SmartNoise Synth, the snsynth package, gives the two methods one interface. This book’s environment does not include it, so the call below did not run. Install it in an environment of its own.

# smartnoise-synth 1.0.8: not installed in this book's environment, not run
from snsynth import Synthesizer

synth = Synthesizer.create("aim", epsilon=1.0, delta=1e-6)
synth.fit(adult_pandas, categorical_columns=["education", "sex", "race", "occupation", "income"])
rows = synth.sample(48_842)

A synthetic table is accurate on the tables that it measured, by construction. So evaluate it on other queries, but not freely on the private data. If you keep the best of several runs, judged against the private data, you select on that data. Also, each extra run spends the generator’s budget again. So score candidate settings on a public dataset of the same shape, or charge the comparisons to the budget. A generator trained without DP is not anonymised, however synthetic its rows look.

18.6 Private multiplicative weights

The synthetic-data tools keep the select, measure and update loop of the multiplicative weights exponential mechanism (MWEM) of Hardt, Ligett and McSherry (2012). MWEM is the practical form of private multiplicative weights, and it keeps a guessed histogram with one weight for each possible record, 256 in the eight-attribute example. In each of a fixed number of rounds, it uses the exponential mechanism to select a query that the guess answers badly. Then it measures that query with fresh Laplace noise and moves the guess toward the measurement. The number of corrections has a limit for all numbers of queries, so the error grows only with the logarithm of the number of queries.

That pays off only for very large sets of queries. On the eight-attribute example at privacy level 1, with 38 rounds, the largest error of MWEM is 0.078. That is better than Laplace noise, but about two times worse than Gaussian noise. Its running time also grows with the number of possible records, which limits it to a few attributes.

If you implement it, fix the number of rounds before you see the data, from the error bound, which uses only public quantities. Measure each query with fresh noise, because the scores of the selection step are exact and must not leak. Release the average of the guesses, not the last one, because the accuracy guarantee covers only the average. For queries that arrive one at a time, an online form pays only for its corrections (Adaptive data analysis).

18.7 Cheat sheet

Rules of thumb

  • Take the list of cells from a codebook, never from the private data.
  • Add noise to whole tables, scaled to the set of tables, and post-process freely afterwards.
  • Fit synthetic data once, and never pick the best of several runs on the private data.

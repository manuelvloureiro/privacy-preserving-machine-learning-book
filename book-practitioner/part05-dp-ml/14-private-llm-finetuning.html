48  Fine-tune a language model privately with LoRA

48.1 Why this matters

You have a pretrained language model and private text, such as support tickets or clinical notes. You want the model to learn from that text without being able to repeat it. Yet a model fine-tuned without privacy can write out a phone number or a password that was often in its training text (Memorization and training-data extraction). The fix is to fine-tune with the differential privacy (DP) version of stochastic gradient descent (SGD), called DP-SGD. It costs least when it trains only a small adapter on the frozen model, which is often as accurate as training every weight (Public data and private fine-tuning). Here the adapter is low-rank adaptation (LoRA), from Hugging Face’s peft library, and Opacus does the private training.

The model is Pythia-14m, a public language model of 14 million parameters from EleutherAI. The private text is Tiny Shakespeare, a million characters of Shakespeare’s plays. The script fine-tunes the model twice, once without privacy and once at a privacy loss \(\varepsilon\) of 8 for each sequence of training text. It first plants made-up secrets, called canaries, in the text, so that you can see what each model memorized. The script practitioner_lora.py runs in a few minutes without a GPU.

uv run python code/part05-dp-ml/practitioner_lora.py

48.2 Fix the privacy unit, n and δ

The guarantee protects one unit, so decide first what the unit is. A language model trains on fixed-length sequences of tokens, the word pieces its tokenizer cuts text into. The script cuts the text into sequences of 32 tokens, about one or two lines of verse, and makes each sequence the unit. To keep the run short, it uses only the first 1,024 sequences for training and the last 128 as a held-out set.

sequences of 32 tokens: 10,632  training n=1,024  held out 128
delta=1e-04 (privacy unit: one training sequence)

The slack \(\delta\) is the small additive term the guarantee allows beside \(\varepsilon\). The book’s default for \(n\) units is \(\delta \le 1/n^{1.1}\), rounded down to a power of ten (Choosing ε). For 1,024 sequences that is \(10^{-4}\).

A sequence is the right unit for this demonstration, but rarely in production. One person’s document spans many sequences, and one user writes many documents, so a guarantee per sequence protects a person much less than it seems. In production, make the unit a document or a user, and bound how many sequences each contributes. Then set \(\delta\) from the number of users (User-level differential privacy).

48.3 Plant canaries

To check memorization later, you need secrets whose presence you control. The script writes canaries into the training text. Each is a sentence such as “the pin of Alice is 8 6 5 2 3”, whose last five digits are the secret. There are four groups of three canaries, inserted 1, 4, 16 and 64 times each. Three more, the controls, are drawn the same way but never inserted, so they show what an unseen secret scores in the audit of Section 48.9.

def insert_canaries(
    train: torch.Tensor, canaries: list[Canary], tokenizer: PreTrainedTokenizerBase, rng: np.random.Generator
) -> torch.Tensor:
    """Write each copy of each canary over the start of a different training sequence."""
    train = train.clone()
    total = sum(c.copies for c in canaries)
    rows = iter(rng.choice(len(train), size=total, replace=False).tolist())
    for canary in canaries:
        tokens = torch.tensor(tokenizer(canary.text)["input_ids"])
        for _ in range(canary.copies):
            train[next(rows), : len(tokens)] = tokens
    return train

Each copy overwrites the start of a different training sequence, so the 255 copies take up a quarter of the training set. That is far denser than secrets in real data, and deliberately so, because it lets a model this small memorize within a short run. The audit then has a positive control, a model known to leak.

canary sequences: 255 (3 canaries each at (1, 4, 16, 64) copies)
tokens per secret: [5]
candidates: 2,000  exposure cap 10.97 bits  (full space 16.61)

The digits are separated by spaces so that every possible secret is exactly five tokens long, which the second line confirms over 1,000 random secrets.

48.4 Load a public model and tokenizer

Everything not trained privately must come from outside the private data. That includes the tokenizer, whose vocabulary would leak rare words if it were built from the private text. So the weights and the tokenizer both come from the same public checkpoint, Pythia-14m, pinned to one revision. The script loads the model in float32, because transformers loads some checkpoints in float16, which is far slower on a CPU.

The guarantee then covers the private text given the pretrained model, and says nothing about the model’s own training data. Here that caveat is real, because Pythia was pretrained on the Pile, which includes Project Gutenberg’s books and so very likely Shakespeare’s plays. That is harmless here, but with real data, check for overlap with the public model’s training data (Public data and private fine-tuning).

48.5 Choose what to train

DP-SGD adds noise to every weight it trains. So the noise on the averaged gradient grows with the square root of the number of trained weights, but the clipped signal does not (Public data and private fine-tuning). That makes the choice of trainable weights one of the two main levers on accuracy, with the learning rate. LoRA freezes each pretrained matrix and learns a correction to it, the product of two thin factors whose width is the rank.

attention_and_mlp = ["query_key_value", "dense", "dense_h_to_4h", "dense_4h_to_h"]  # every linear layer
config = LoraConfig(r=rank, lora_alpha=2 * rank, target_modules=attention_and_mlp, lora_dropout=0.0)
lora_model = get_peft_model(model, config)  # freezes the pretrained weights
trainable_count = sum(p.numel() for p in lora_model.parameters() if p.requires_grad)
total_count = sum(p.numel() for p in lora_model.parameters())
print(f"trainable parameters: LoRA {trainable_count:,}  full fine-tuning {total_count - trainable_count:,}")
full model parameters: 14,067,712
trainable parameters: LoRA 98,304  full fine-tuning 14,067,712

By default the adapters have rank 8 and sit on every linear layer, in attention and in the feed-forward blocks. They train 98,304 weights, against about 14 million that full fine-tuning would train. lora_alpha scales the adapters’ correction, set to the usual twice the rank. For a real task, choose the rank and the layers on public data, because a choice made from private runs costs privacy (Hyperparameter tuning).

48.6 Make the model Opacus-compatible

Opacus needs one gradient per sequence, and layers that mix the records of a batch, such as batch normalization, make that impossible. Opacus’s ModuleValidator.validate lists such layers before you train.

validator errors: 0

Pythia has none, and only the adapters train in any case. They are ordinary linear layers, which Opacus’s default hooks handle, so the script passes grad_sample_mode="hooks". Opacus computes per-sequence gradients only for the weights that require gradients, so the 14 million frozen weights add no cost. Call model.train() before wrapping a model you have just evaluated, since Opacus rejects one in evaluation mode. After training, the hooks stay attached and slow down everything the model does next. So the script calls remove_hooks() before it evaluates the private model.

48.7 Calibrate and train

Fix the target \(\varepsilon\), \(\delta\), the sampling rate and the number of epochs, and let the accountant find the noise. The script asks for \(\varepsilon = 8\) over 3 epochs with an expected batch of 32 sequences. The sampling rate \(q\), the share of the data in an average batch, is then \(32/1{,}024\), so the 3 epochs take 96 steps. The accountant is the privacy loss random variable (PRV) accountant, which computes \(\varepsilon\) almost exactly (Report and review an ε claim).

privacy_engine = PrivacyEngine(accountant="prv")
private_model, optimizer, loader = privacy_engine.make_private_with_epsilon(
    module=model,
    optimizer=optimizer,
    data_loader=loader,  # replaced by Poisson sampling with rate BATCH / n
    target_epsilon=epsilon,
    target_delta=delta,
    epochs=EPOCHS,
    max_grad_norm=MAX_GRAD_NORM,
    grad_sample_mode="hooks",
)
print(f"noise multiplier: {optimizer.noise_multiplier:.3f}")

The training loop is an ordinary one. Opacus’s loader draws Poisson batches, in which each sequence joins each batch independently with probability \(q\).

for (batch,) in loader:  # each batch holds a random number of sequences
    optimizer.zero_grad()
    loss = private_model(input_ids=batch, labels=batch).loss
    loss.backward()  # Opacus's hooks keep one gradient per sequence
    optimizer.step()  # clips each one to MAX_GRAD_NORM, sums, adds noise
    steps += 1
noise multiplier: 0.553
sample rate q=0.03125  steps=96  noise multiplier=0.553
epsilon (Opacus PRV)=7.99  epsilon (dp_accounting PLD)=7.98  at delta=1e-04

The noise multiplier is the noise’s standard deviation in units of the clipping norm, MAX_GRAD_NORM, which the script sets to 1. The last line cross-checks the claimed \(\varepsilon\) of 8 with the privacy loss distribution (PLD) accountant of Google’s dp_accounting. The two values agree to within rounding.

Both runs use AdamW at a learning rate of \(10^{-3}\), and the private run differs only by clipping, noise and Poisson sampling. That learning rate, the rank and the epochs were chosen in a few non-private trial runs on the same text. A real run must choose them on similar public text, such as other public-domain plays, or pay for the trials in \(\varepsilon\) (Hyperparameter tuning).

Two more settings change for a real run. With more data, use batches in the thousands, not 32. Opacus’s BatchMemoryManager splits them into physical batches that fit in memory (Train a model with DP-SGD). And a model you release needs secure_mode=True in PrivacyEngine, whose cryptographically secure noise cannot be seeded, which is why the script leaves it off.

48.8 Evaluate

A language model is judged by how well it predicts held-out text. The script measures the mean cross-entropy per token on the 128 held-out sequences, and its exponential, the perplexity. A perplexity of 159.3 means the model is as unsure as if it chose among about 159 equally likely tokens. So lower is better.

held-out loss pretrained: 5.306 nats/token  perplexity 201.6
held-out loss LoRA non-private: 5.071 nats/token  perplexity 159.3
held-out loss LoRA DP eps=8: 5.044 nats/token  perplexity 155.1

Both fine-tuned models improve on the pretrained one, and the private model is no worse than the non-private one. On one seed, its slightly lower perplexity means only that DP costs nothing measurable here. Both gains are modest, because a quarter of the training sequences begin with canaries rather than Shakespeare.

Do not expect privacy to be this cheap on every task. This run is short, trains few weights, and uses text that is very likely in the pretraining data already. With a harder task or a smaller \(\varepsilon\), compare the private model with both baselines at several budgets, as Train a model with DP-SGD does.

48.9 Check memorization

The canaries show what perplexity cannot, whether the model will repeat a secret. The script measures each canary in two ways, first by extraction. It gives the model the prefix “the pin of Alice is” and lets it write the likeliest next token five times. Then it checks whether the result is the secret.

@torch.no_grad()
def greedy_completion(model: PeftModel, tokenizer: PreTrainedTokenizerBase, prefix: str) -> str:
    """The five tokens the model writes after the prefix when it always picks the likeliest one."""
    ids = tokenizer(prefix, return_tensors="pt")["input_ids"]
    for _ in range(5):
        next_token = model(input_ids=ids).logits[:, -1].argmax(dim=-1, keepdim=True)
        ids = torch.cat([ids, next_token], dim=1)
    return tokenizer.batch_decode(ids[:, -5:])[0].strip()

The second is the exposure of Memorization and training-data extraction. It ranks the canary’s secret among random secrets of the same format by how likely the model finds each, and turns the rank into bits. The script’s likelihood is the summed log-probability of the five digits. Each bit halves the number of guesses an attacker needs.

@torch.no_grad()
def secret_scores(model: PeftModel, tokenizer: PreTrainedTokenizerBase, prefix: str, secrets: list[str]) -> Scores:
    """Summed log-probability of each secret's five digit tokens after the prefix."""
    prefix_ids = tokenizer(prefix)["input_ids"]
    rows = [prefix_ids + tokenizer(" " + s)["input_ids"] for s in secrets]
    ids = torch.tensor(rows)  # every secret is five tokens, so the rows have equal length
    logits = model(input_ids=ids[:, :-1], logits_to_keep=5).logits  # the predictions of the five digits
    logprobs = logits.log_softmax(dim=-1).gather(-1, ids[:, -5:, None])
    return logprobs.sum(dim=(1, 2)).double().numpy()


def canary_exposure(
    model: PeftModel, tokenizer: PreTrainedTokenizerBase, canary: Canary, candidates: list[str]
) -> tuple[float, float]:
    """The exposure of the canary's secret among the candidates, measured and extrapolated past the cap."""
    candidate_scores = scores_batched(model, tokenizer, canary.prefix, candidates)
    score = float(scores_batched(model, tokenizer, canary.prefix, [canary.secret])[0])
    return exposure(score, candidate_scores), extrapolated_exposure(score, candidate_scores, SECRET_SPACE)

No library installed with this book computes exposure, so exposure and extrapolated_exposure come from the book’s helper module practitioner_privacy_tests.py, after TensorFlow Privacy’s versions. With 2,000 random candidates, a canary that beats them all reaches a cap of 10.97 bits. A secret the model has never seen has a random rank and averages about 1.44 bits (\(\log_2 e\)). Each line below gives a group’s mean exposure, the same past the cap, and how many of its three secrets greedy decoding wrote out.

non-private 1 copies: mean exposure 2.0 bits  extrapolated 2.0  extracted 0/3
non-private 4 copies: mean exposure 5.9 bits  extrapolated 5.7  extracted 0/3
non-private 16 copies: mean exposure 10.0 bits  extrapolated 13.0  extracted 0/3
non-private 64 copies: mean exposure 11.0 bits  extrapolated 16.3  extracted 3/3
non-private controls: mean exposure 1.4 bits  extrapolated 1.5  extracted 0/3
DP 1 copies: mean exposure 0.9 bits  extrapolated 0.9  extracted 0/3
DP 4 copies: mean exposure 0.6 bits  extrapolated 0.6  extracted 0/3
DP 16 copies: mean exposure 4.2 bits  extrapolated 4.3  extracted 0/3
DP 64 copies: mean exposure 4.0 bits  extrapolated 3.9  extracted 0/3
DP controls: mean exposure 2.2 bits  extrapolated 2.2  extracted 0/3

The non-private model, the positive control, leaks. Exposure rises with the number of copies, from 2.0 bits for one copy to the cap for 64. The model writes out all three 64-copy secrets. The extrapolated column sees past the cap by fitting a skew-normal distribution, a normal with one heavier tail, to the candidates’ scores. It puts the 64-copy secrets near the 16.61 bits of the whole space.

The 4-copy canaries are the instructive case. Two of the three reach 6.9 and 8.2 bits, yet none is extracted, so exposure detects memorization that extraction alone would miss.

Nothing can be extracted from the private model. Its canaries with 1 or 4 copies score no higher than its controls. Their 2.2 bits are within the scatter of a mean over three secrets. Still, DP limits the effect without erasing it, since the canaries with 16 and 64 copies still average about 4 bits.

The guarantee allows that, because \(\varepsilon = 8\) protects one sequence, while a canary with many copies is many sequences. Group privacy bounds a group of units at about their number times \(\varepsilon\). So 16 copies get \(16 \times 8\), far too much to promise anything (User-level differential privacy). A secret that a user repeats across many documents is the same case, one more reason to make the unit the user.

Two cautions apply. Because the canaries are so dense, a real non-private model may leak less than this one, and a real audit should plant fewer copies. And three canaries per group is a small sample. For a fuller assessment before release, run the attacks of Pre-release privacy risk assessment. For a statistical lower bound on \(\varepsilon\), run the one-run audit of Auditing private training.

48.10 Variants

Three variants matter for real models: ghost clipping, LoRA on GPT-2, and packages that wrap the whole loop. The block below shows them with pinned versions, and it was not run.

# opacus==1.6.0: ghost clipping, when per-sequence gradients do not fit in memory
model, optimizer, criterion, loader = privacy_engine.make_private_with_epsilon(
    module=model, optimizer=optimizer, data_loader=loader, criterion=torch.nn.CrossEntropyLoss(),
    target_epsilon=8.0, target_delta=1e-4, epochs=3, max_grad_norm=1.0, grad_sample_mode="ghost",
)
logits = model(input_ids=batch).logits[:, :-1]                 # predict each next token
loss = criterion(logits.flatten(0, 1), batch[:, 1:].flatten(), shape=logits.shape)
loss.backward()                                                # norms first, then the clipped sum

# peft==0.21.2: GPT-2 stores its attention as Conv1D, with the weight transposed
LoraConfig(r=8, lora_alpha=16, target_modules=["c_attn"], fan_in_fan_out=True)

# dp-transformers==1.0.0 (Microsoft): Opacus inside the Hugging Face Trainer
# private-transformers (Li et al.): install from its GitHub repository, pinned to a commit

Ghost clipping gets each sequence’s gradient norm without storing the gradient, so memory no longer holds one gradient per sequence (DP-SGD).

48.11 Report

The release statement names the unit, here one sequence of 32 tokens, with the number of units \(n\) and the slack \(\delta\). It names the accountant and its three inputs, which are the noise multiplier, the sampling rate and the number of steps. It says that the guarantee covers the private text given the pretrained model, named with its revision. It says how the hyperparameters were chosen, here by non-private trials on the private text, which a real release could not claim for free. Attach the canary audit as evidence, with its caveats. Release and governance assembles all of this into a record and a statement.

What ships is the adapter. With --save-adapter FOLDER, the script saves it after remove_hooks() and loads it back onto the same pinned checkpoint.

private.save_pretrained(path)  # only the adapter weights and config, after Opacus's hooks are removed
base_model = AutoModelForCausalLM.from_pretrained(folder, dtype=torch.float32)  # the same pinned checkpoint
reloaded = PeftModel.from_pretrained(base_model, path)

The folder holds only the adapter, so the statement names the base checkpoint and revision it fits. The guarantee covers the adapter and anything computed from it.

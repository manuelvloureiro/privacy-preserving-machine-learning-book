42  DP-SGD

42.1 Why this matters

Nearly every deep-learning system that satisfies differential privacy (DP) runs one algorithm. It is stochastic gradient descent (SGD) with each example’s gradient clipped to a fixed length and Gaussian noise added at every step, called DP-SGD (Abadi et al. 2016). Clipping limits how far one record moves each step, whatever the model, and the noise hides that move (Private empirical risk minimization). An accountant then adds up the cost of every step into one privacy level, the \(\varepsilon\) of the guarantee. It comes with \(\delta\), a small additive slack that the guarantee allows on top of \(\varepsilon\).

The accountant sees only the noise, the sampling rate (the chance that a record joins a batch) and the number of steps, never the model. So those three decide \(\varepsilon\), and the clipping norm and the step size are free to be tuned for accuracy. Most failures come from code that breaks an assumption of the privacy proof, so the checks matter as much as the settings. Train a model with DP-SGD does the whole job in Opacus.

42.2 The algorithm and its guarantee

A training set holds \(n\) records. The gradient of one record’s loss is its per-example gradient, written \(g_i\) for record \(i\). DP-SGD repeats five operations at every step.

  1. Sample a batch. Each record enters independently with probability \(q\), the sampling rate, which is called Poisson sampling.
  2. Compute the per-example gradient of each record in the batch.
  3. Clip each gradient longer than the clipping norm \(C\) to length \(C\).
  4. Sum the clipped gradients, and add Gaussian noise with standard deviation \(\sigma C\) to each coordinate of the sum, where the noise multiplier \(\sigma\) measures the noise in units of \(C\).
  5. Divide the noisy sum by the expected batch size \(B = qn\), a fixed public number, and take a step of size \(\eta\) in the opposite direction.

Write \(w_t\) for the weights at step \(t\) and \(S_t\) for its batch. The Gaussian noise \(\xi_t\) is drawn afresh, independently on each coordinate, and the update is \[w_{t+1} = w_t - \frac{\eta}{B}\Big(\sum_{i\in S_t}g_i\min\Big(1, \frac{C}{\|g_i\|}\Big) + \xi_t\Big), \qquad \xi_t \sim \mathcal N(0, \sigma^2C^2I). \tag{42.1}\] Releasing every intermediate set of weights then satisfies \((\varepsilon, \delta)\)-DP for add/remove neighbours, datasets that differ because one has a record the other lacks (Amplification by subsampling).

This part’s running example trains a small network on 10,000 synthetic records (Section 42.7). It runs 10,000 steps with \(\sigma = 1\), and each record joins a batch with probability 0.01. The Rényi differential privacy (RDP) accountant, a standard upper bound that is slightly loose, gives it \(\varepsilon = 6.71\) at \(\delta = 10^{-5}\). To pick \(\sigma\) for a target \(\varepsilon\) instead, let the accountant you will report solve for it. Train a model with DP-SGD does this in one Opacus call (Calibrate and account a DP-SGD run).

Choose \(\delta\) by the book’s default, \(\delta \le 1/n^{1.1}\) rounded down to a power of ten. That keeps it safely below \(1/n\) (Choosing ε). Here \(n\) counts people, and for the running example’s 10,000 records, one per person, the rule gives its \(10^{-5}\).

42.3 The implementation checklist

The guarantee rests on four properties of your code, and code that breaks one still trains and reports as before.

First, one record must move the clipped sum by at most \(C\). Batch normalization breaks this, because its statistics let one record change every other record’s gradient. So private models use group or layer normalization, which normalize each example on its own. With strict=False, Opacus’s validator lists the layers to replace instead of raising an error.

from opacus.validators import ModuleValidator
from torchvision.models import resnet18

model = resnet18(weights=None)
print(len(ModuleValidator.validate(model, strict=False)))  # 20
model = ModuleValidator.fix(model)
print(len(ModuleValidator.validate(model, strict=False)))  # 0

The clipping norm must also be fixed in advance, from public data or from a private estimate. A \(C\) read off the current batch makes the size of the noise depend on the data, and that dependence leaks information the accountant does not count.

Second, the accountant must assume the sampler the code actually runs (Amplification by subsampling). The Poisson accountant’s saving comes from each record’s chance of being left out. A loader that shuffles once per epoch and cuts fixed batches puts every record in exactly one batch per epoch. That chance is then gone, and the true \(\varepsilon\) can be far above the Poisson number.

Batches of a fixed size, drawn afresh at every step, can still use a Poisson accountant. Give it the batch’s share of the data as the rate and half your noise multiplier, because a record that enters a fixed-size batch pushes another out, so the sum can move by \(2C\). That is expensive, since halving \(\sigma\) raises the running example’s \(\varepsilon\) from 6.71 to 47.42. The rule holds only for add/remove neighbours, and Part 4 gives what to account for under the others.

Third, divide the noisy sum by the public number \(B\), never by the actual batch size. The actual size is one larger when the protected record is drawn, so dividing by it reveals whether it was, and the accountant does not count that leak.

Fourth, the accountant must count every step that touched the data, including those of runs discarded during tuning.

Beyond the proof, state the neighbouring relation next to every \(\varepsilon\), and make data-dependent preprocessing private too. The guarantee covers one record, so a person with many records needs user-level privacy. And the proof assumes exact Gaussian noise, which ordinary floating-point sampling does not produce, so turn on Opacus’s secure_mode=True for a model you release (Discrete and floating-point-safe mechanisms).

42.4 Clipping and the step size

Clipping must happen per example. PyTorch’s torch.nn.utils.clip_grad_norm_ clips the gradient of a whole batch, which bounds nothing about any single example, so it gives no privacy at any threshold.

The clipping norm does not change \(\varepsilon\), but it sets the two ways clipping costs accuracy. A small \(C\) clips more gradients, so records with large gradients count for less, and they are often rare examples (Disparate impact). A large \(C\) instead means more noise, since the noise is \(\sigma C\). When every gradient is clipped, each has length exactly \(C\), and the noise is proportional to \(C\) too. So only the product \(\eta C\) of the step size and the clipping norm matters. The practical recipe is to clip hard and tune that one number. On the running example at \(\sigma = 1\), holding \(\eta C\) at 0.25 keeps test accuracy at 0.9599 or above for every \(C\) up to 0.3. With the step size held at 0.5 instead, \(C = 10\) drops it to 0.8347.

Noise also changes the best step size. On the logistic problem of Optimization, adding noise moves the best step on a grid down from 0.178 to 0.056. Clipping pulls the other way, because clipped gradients are shorter, which is why private runs often start from a step several times the non-private one. The two effects do not cancel predictably. So search the step again whenever \(\sigma\) or \(C\) changes, and count the search’s runs in \(\varepsilon\).

Gradient norms also drift. The running example’s median per-example norm falls from 3.592 to 0.006 in a thousand steps, so a \(C\) that clips everything early clips only a minority later. Adaptive clipping is the private estimate that the checklist allows, since it moves \(C\) toward a quantile of the norms measured by a small private count. Opacus offers it with clipping="adaptive", but this is not a drop-in switch. It takes five more parameters, such as target_unclipped_quantile, the share of gradients to leave unclipped. And because part of the noise budget goes to the count, the gradient gets more noise at the same \(\sigma\).

42.5 Batch size at a fixed budget

Averaging the noisy sum over \(B\) records divides the added noise by \(B\), so larger batches dilute it. At a fixed budget and number of epochs, a larger batch means fewer steps, and the noise multiplier must rise to keep \(\varepsilon\), but more slowly than \(B\) does. For a small sampling rate and a noise multiplier well above 1, the accountant’s cost at a fixed number of epochs depends on \(q/\sigma^2\), so the noise multiplier only has to grow like \(\sqrt q\). Since \(q\) is \(B/n\), the noise on the averaged gradient falls with the batch size, \[\sigma \propto \sqrt{\frac Bn}, \qquad \frac{\sigma C}{B} \propto \frac{C}{\sqrt{Bn}}. \tag{42.2}\] Small batches are worse still, because they need a noise multiplier near or below 1, where subsampling saves much less.

So choose the largest batch your hardware allows, with a larger step size for the fewer steps. When the batch does not fit in memory, Opacus’s BatchMemoryManager splits the logical batch, the one the sampler draws, into physical batches that fit. It still steps once per logical batch, so the sampling rate and the accounting stay the same.

42.6 Making it fast

Computed one record at a time, DP-SGD can run tens or hundreds of times slower than ordinary training. Of three fixes, the first two are free. Vectorized per-example gradients, from torch.func.vmap or Opacus’s hooks, compute the same clipped sum in parallel. Ghost clipping also saves memory, because it gets each example’s gradient norm from each layer’s inputs and back-propagated errors without forming the gradient. Opacus turns it on with grad_sample_mode="ghost", and make_private then also returns a loss function to train with.

Microbatching is the costly fix. It clips the average gradient of each fixed group of \(m\) records instead of each record’s gradient. One record can then change its group’s clipped average by up to \(2C\), so the noise must double. And since the update divides it by the \(B/m\) groups rather than by \(B\) records, the noise on each coordinate of the averaged update becomes \[2m\cdot\frac{\sigma C}{B}. \tag{42.3}\] On the running example at \(\sigma = 1\), groups of 4 cut test accuracy from 0.9589 with per-example clipping to 0.9336, so use it only as a last resort.

Clipping without noise scores slightly above non-private SGD here, so the whole loss comes from the noise, and it grows steeply as \(\varepsilon\) shrinks. Going from \(\varepsilon = 8\) to 4 costs half a point, while halving it from 1 to 0.5 costs almost 10. The total length of the noise on a step also grows with the square root of the number of trained weights. The clipped signal cannot exceed \(C\), so a smaller model or public pretraining often helps.

42.8 Cheat sheet

Rules of thumb

  • Fix \(\varepsilon\), \(\delta\) and the number of epochs first, since they are the contract. Then choose the batch, let the accountant set \(\sigma\), and tune the step size last.
  • Find the \(\varepsilon\) below which accuracy collapses on your task before you promise a budget.

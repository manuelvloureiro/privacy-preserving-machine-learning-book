40  Hyperparameter tuning and private selection

40.1 Why this matters

Stochastic gradient descent (SGD) with clipped gradients and Gaussian noise satisfies differential privacy (DP) at the level its accountant reports for one run, and is called DP-SGD. But nobody trains once. You try a grid of step sizes, score each model on a validation set and ship the best, and every run and every score touched private data. So the search leaks, and you must pay for it honestly.

The answer depends on one choice. With a fixed number of runs, releasing the best can cost as much as releasing all of them. For example, one run of this part’s running example costs a privacy level \(\varepsilon\) of 6.71, but a grid of 10 runs costs 27.23. Now draw the number of runs at random, from a distribution fixed in advance. The same expected number of runs then costs between 10.08 and 13.67.

40.2 The procedure and the report

First, spend private runs only where you must, because the cheapest tuning is tuning you don’t do on private data. Runs on public or proxy data cost nothing, and so do published DP-SGD settings for similar tasks. Fix a large batch, the number of epochs and a small clipping norm in advance. Below the typical gradient norm only the clipping norm’s product with the step size matters, so that product is often the only thing left to search (DP-SGD). Use tuners such as Optuna or Ray Tune on private data only for random search, with the number of runs drawn first.

Second, fix the search before you touch the private data. Write down the candidate set, the distribution of the number of runs, the score and the validation set. Deciding to “try a few more”, or restarting a search whose result disappoints, makes the search depend on the data, and no theorem covers that.

Third, make the score private, with a disjoint validation set and noise on each count of correct predictions (Section 40.6). Fourth, account for the whole search. For two or three candidates, charge for every run by composition (Section 40.4). For more, use random search with a random number of runs (Section 40.5). Count every run that touched the private data, including crashed runs, debugging runs and evaluations used for early stopping.

Log the candidate set, the drawn number of runs, and each run’s hyperparameters, accounting settings and noisy score. Opacus’s get_epsilon reports one run only, so compose the runs in an accountant yourself. If you trained 50 configurations at \(\varepsilon = 2\) each, the honest answer is not 2 but the composition of all 50, which grows almost linearly at large \(\varepsilon\) (Table 40.1).

Finally, report two numbers. The \(\varepsilon\) of the released run says what the model alone would leak, while the \(\varepsilon\) of the whole procedure is what the release actually guarantees. For the Poisson search of Section 40.7, a complete report reads as follows.

DP-SGD with Poisson sampling rate 0.01, clipping norm 0.5, noise multiplier 1.53 and 1,000 steps. One run satisfies \((0.98, 10^{-5})\)-DP. The step size was selected by random search over \(\{0.0625, 0.125, \dots, 8\}\), with a Poisson number of runs with mean 8. Each run was scored by its correct predictions on a disjoint validation set of 5,000 records, plus Gaussian noise of standard deviation 20. The whole procedure satisfies \((1.99, 10^{-5})\)-DP by the Rényi bound of Papernot & Steinke (2022, Theorem 6), for add/remove neighbours at the record level.

An audit tests only the released model, so it cannot catch a missing tuning charge.

40.3 The best of k runs can cost k runs

A common argument says that choosing among eight step sizes reveals at most three bits. It is wrong, because the release is a whole private run, picked because of how it came out. If each run is a randomized response that comes out “good” or “bad”, the best of \(k\) runs is bad only if every run is bad. The evidence from that event multiplies across runs, so the best of \(k\) runs is exactly \(k\varepsilon\)-DP.

Tuning without privacy and then training once privately does not escape this. Even a single chosen regularization weight can reveal whether a few outliers were in the training set (membership inference).

40.4 Paying by composition

The safe answer is to charge for every run. The best run is computed from the runs’ outputs alone, so it costs at most what releasing all of them costs (Properties of DP). Rényi differential privacy (RDP) describes each run by a curve \(\varepsilon(\lambda)\) over orders \(\lambda\) (Rényi DP). The curves of \(k\) runs add, so the whole search has a curve \(\varepsilon_A\) of at most \[\varepsilon_A(\lambda) \le k\,\varepsilon(\lambda). \tag{40.1}\] For DP-SGD this is simple, because \(k\) runs of a number of steps \(T\) cost exactly as much as one run of \(kT\) steps.

In the running example, ten runs cost 4.06 times one run, because the conversion to \(\varepsilon\) with a small slack \(\delta\) pays its fixed cost only once. To keep ten runs at the budget of one, each run needs a noise multiplier of 2.45, which costs accuracy.

40.5 A random number of runs

The way past the \(k\varepsilon\) barrier is to draw the number of runs at random, independently of the data. Then “every run was bad” is mostly explained by the search stopping early. Liu & Talwar (2019) showed this first for random stopping, which stops after each run with a fixed probability and costs \(3\varepsilon\) for \(\varepsilon\)-DP runs.

For DP-SGD, use the version of Papernot & Steinke (2022), which works with RDP curves. First fix the candidate set and a distribution for the number of runs \(K\). It is either Poisson or truncated negative binomial, a family with a shape parameter \(\eta\). Then draw \(K\) and run that many candidates drawn at random from the set. Release the best by a noisy score. The whole search then costs about one run, plus a term that grows only with the logarithm of the expected number of runs, \[\varepsilon_A(\lambda) \le \varepsilon(\lambda) + \frac{\ln\mathbb E[K]}{\lambda - 1} + (\text{a term set by the shape of } K). \tag{40.2}\] For pure \(\varepsilon\)-DP runs it tends to \((2 + \eta)\varepsilon\), so the logarithmic distribution (\(\eta = 0\)) gives \(2\varepsilon\) and the geometric (\(\eta = 1\)) gives \(3\varepsilon\). Google’s dp_accounting computes it, by composing in an RdpAccountant a RepeatAndSelectDpEvent(event, mean, shape) that wraps one run’s event. Its shape is infinite for Poisson, 1 for geometric and 0 for logarithmic.

import dp_accounting
run = dp_accounting.SelfComposedDpEvent(
    dp_accounting.PoissonSampledDpEvent(q, dp_accounting.GaussianDpEvent(sigma)), steps)
search = dp_accounting.dp_event.RepeatAndSelectDpEvent(run, mean=8, shape=float("inf"))
acc = dp_accounting.rdp.RdpAccountant()
acc.compose(search)
print(acc.get_epsilon(1e-5))

A smaller \(\eta\) gives a cheaper bound but more often stops after a single run, and the Poisson bound suits runs that are already very private. A random number of runs may also miss the best candidate. On a grid of 8 with 8 runs on average, it never tries the best one with probability 0.4667.

The theorems have three conditions, and each is easy to break. First, each run must draw its candidate independently from a fixed distribution, which is random search. So Bayesian optimization, which picks each candidate from earlier scores, is not covered and needs adaptive composition. Second, the number of runs must be drawn independently of the data. Third, the score that ranks the runs must be part of each run’s private output.

40.6 Selecting by a noisy validation score

When the candidates are fixed, such as public pretrained checkpoints, only the choice among them uses private data. That is a pure selection problem, which Selection solved. Score each candidate by its number of correct predictions on a private validation set. One record changes such a count by at most 1, while an accuracy divides by a size that is itself private. Then the exponential mechanism at a budget \(\varepsilon\) picks a candidate whose expected shortfall from the best count is at most \[\frac{2}{\varepsilon}(\ln k + 1) \tag{40.3}\] correct predictions, among \(k\) candidates. On a validation set of \(m\) records, that is an accuracy gap of at most \(2(\ln k + 1)/(\varepsilon m)\). For example, choosing among eight trained models on 5,000 validation records costs about a tenth of a point of accuracy at a budget of 0.1.

With disjoint training and validation sets, each record sits in one of them, so a search over trained candidates costs the larger of the training cost and the selection cost, not their sum.

The random-number bounds need a private score too. An exact validation accuracy leaves the validation records unprotected, so add Gaussian noise to each run’s count of correct predictions. With noise of standard deviation 20, one noisy count costs 0.182. Eight of them stay below the training runs’ cost at every order the conversion uses, so they add nothing to the total.

Tuning on proxy data, a related task labelled by a different random network, is nearly free.

40.8 Cheat sheet

Rules of thumb

  • Fix the search before touching the private data, and never “try a few more” or restart it.
  • Report the whole search’s \(\varepsilon\), never the selected run’s alone.
  • Account for Bayesian optimization as adaptive composition, not as a fixed candidate set.
  • Never select by exact accuracy on a private validation set.

51  Disparate impact

51.1 Why this matters

A private model’s test accuracy is an average over everyone, so it cannot show which people lose the accuracy that privacy costs. Bagdasaryan, Poursaeed & Shmatikov (2019) trained networks with differential privacy (DP), using the private form of stochastic gradient descent (SGD) called DP-SGD. They found that the lost accuracy fell mostly on under-represented groups, and called this the disparate impact of DP.

So a model that is a point worse on average can be ten points worse for one group, often a small group that privacy is meant to protect. Before you ship a private model, measure its cost for each group against a non-private baseline, with a confidence interval on every number.

51.2 Evaluating a private model per group

Decide which groups matter before you look at any results, so that the results cannot steer the choice. Then train a non-private baseline with the same data and recipe. A gap between groups may exist without privacy, so what DP is responsible for is how far each group’s own accuracy drops when training becomes private.

Write \(\mathrm{acc}_g\) for a model’s accuracy on the test records of group \(g\). Private training is random, so its accuracy is averaged over several training runs, written \(\mathbb E\). The privacy cost \(\pi_g\) is then the accuracy the group loses when the same data and hyperparameters are trained privately, \[\pi_g = \mathrm{acc}_g(\text{non-private}) - \mathbb E\big[\mathrm{acc}_g(\text{private})\big]. \tag{51.1}\] DP has disparate impact when groups have different privacy costs.

Every accuracy needs an interval. Each test record is either classified correctly or not, so a group’s accuracy is a binomial proportion. Its exact Clopper–Pearson interval contains the true accuracy in at least 95% of test samples (Hypothesis testing). The gap between two groups needs its own interval. Write \(\hat p_g\) for group \(g\)’s measured accuracy and \(m_g\) for its number of test records. For two groups \(a\) and \(b\) measured on disjoint test records, the estimates are independent, so their variances add. For large counts, 1.96 standard deviations on each side give an approximate 95% interval for the gap, \[(\hat p_a - \hat p_b) \pm 1.96\sqrt{\frac{\hat p_a(1 - \hat p_a)}{m_a} + \frac{\hat p_b(1 - \hat p_b)}{m_b}}. \tag{51.2}\]

These intervals are wider than most people expect. Suppose a test split holds only 100 records of a minority, and 88 of them are classified correctly. The majority gets 1,812 of its 1,900 records right, an accuracy of 0.954. So the measured gap is 0.074. SciPy gives the minority’s interval, and Equation 51.2 gives the gap’s.

from math import sqrt

from scipy.stats import binomtest

minority = binomtest(88, 100).proportion_ci(confidence_level=0.95, method="exact")
print(f"{minority.low:.3f} {minority.high:.3f}")  # 0.800 0.936

gap, se = 0.954 - 0.880, sqrt(0.954 * 0.046 / 1_900 + 0.880 * 0.120 / 100)
print(f"{gap - 1.96 * se:.3f} {gap + 1.96 * se:.3f}")  # 0.010 0.138

So the gap is real, since its interval excludes zero, but it could be anywhere from one point to fourteen. An interval separates a 5-point gap from zero only with a few hundred test records from the group, and a 1-point gap only with thousands.

The privacy cost needs a different interval, because both models are scored on the same test records, so their accuracies are not independent and Equation 51.2 does not apply. Pair them instead. Among group \(g\)’s \(m_g\) test records, write \(u\) for the number that only the non-private model gets right, and \(v\) for the number that only the private one gets right. One run’s cost is then \((u - v)/m_g\), and for large counts an approximate 95% interval is \[\frac{u - v}{m_g} \pm \frac{1.96}{m_g}\sqrt{u + v - \frac{(u - v)^2}{m_g}}. \tag{51.3}\]

The test records are one source of variation. Training is a second source, and a larger test set does nothing about it. A small group’s accuracy varies far more from one training run to the next than a large group’s. So a comparison of two recipes on one run each can easily reverse for it. Train each recipe several times with different seeds, average the per-run costs and report their spread. fairlearn.metrics.MetricFrame computes any metric per group, but without intervals.

The evaluation itself can also leak. Per-group accuracies on private test data are statistics of that data. To publish them, add noise to each group’s count of correct predictions and count it in a budget of its own (Release statistics with a library). Otherwise keep them in the internal assessment.

51.3 Disparate impact, measured

The script practitioner_dp_sgd.py of Train a model with DP-SGD uses the Adult census data, which predicts whether a person’s income exceeds $50K. It trains a small network once without privacy and once with DP-SGD at a privacy level \(\varepsilon\) of 4 and a slack \(\delta\) of \(10^{-5}\). Then it scores both models on the test rows of each sex, the only attribute it measures. Other attributes, such as race, have much smaller groups and wider intervals. For each group it counts the correct predictions, marked in the boolean array right, and asks SciPy for the exact interval.

in_group = sex == group
correct, total = int(right[in_group].sum()), int(in_group.sum())
interval = binomtest(correct, total).proportion_ci(confidence_level=0.95, method="exact")

Its seed-0 run, uv run python code/part05-dp-ml/practitioner_dp_sgd.py, gives Table 51.1.

Here DP has no measurable disparate impact. Each group loses at most 0.002, well inside its intervals, which overlap almost entirely. It comes from one private run, a single draw of Equation 51.1 rather than its average. The large gap between the groups, 0.924 against 0.808, is there without privacy too, so DP is not responsible for it. Adult is easy, because both groups are large and the whole model loses almost nothing at this budget, 0.846 with DP against 0.847 without.

A small group tells a different story. The full edition’s running example is a synthetic task with 10,000 training records, labelled by a fixed random network. Of these records, 500 form a minority whose inputs come from a different region and follow a different labelling rule (Table 51.2).

The minority pays almost all of the cost. At \(\varepsilon = 4\) the majority loses 0.59 points, while the minority loses 9.34. The cost also depends steeply on the group’s share of the data. At the same budget, a minority with 1% of the training records loses 34.88 points. With 20% of the records, it loses only 2.80. So check every small group, whatever the overall accuracy says.

51.4 Why small groups pay: clipping and noise

DP-SGD loses accuracy through two steps, clipping and noise, and both treat every record alike. The clipping row of Table 51.2 clips without adding noise, so it gives no privacy at all. Yet the minority already loses 4.04 points there, which means clipping by itself treats the groups unequally.

Clipping caps every record’s pull on the update at the clipping norm \(C\), so it cuts back the groups with long gradients hardest. A group’s gradients are long where the model fits it badly, as it does a rare pattern that the rest of the data does not teach. So training gives such a group less weight than its share of the records.

The noise is the same for every group, while a group’s signal grows with its size. So a small group’s signal is the weakest against the noise, and its privacy cost grows roughly like one over its share of the training records. The two causes compound, because the noise acts on the weight that clipping has already shrunk. So a group whose gradients clipping halves pays like a group half its size.

To see which cause hurts your model, measure per-example gradient norms by group. Opacus’s GradSampleModule, the wrapper DP-SGD training already uses, keeps one gradient per row in each parameter’s grad_sample. So one backward pass gives the norms, which stacked_norms combines over all parameters.

wrapped = GradSampleModule(model)  # adds hooks that keep one gradient per row
wrapped.train()
logits: torch.Tensor = wrapped(split.x)
nn.CrossEntropyLoss()(logits, split.y).backward()  # fills p.grad_sample for every weight p
norms = stacked_norms(wrapped)

Group the norms by each row’s group label, kept beside the batch but not fed to the model. To measure a model that Opacus has already wrapped, copy its weights into a fresh, unwrapped module first, because GradSampleModule refuses a model that already carries its hooks. Log each group’s median norm and fraction clipped as training goes on, because the groups can separate late. At initialization on Adult, the median norm is 1.444, and \(C = 1\) clips every row, whatever its group.

51.5 Mitigations and what they cost

At a fixed budget, a change to the training recipe only moves the cost between the groups or between clipping and noise (Table 51.3). Only the last row, which changes the data, the starting model or the budget, reduces it.

Oversampling costs the group’s privacy, because a record’s guarantee depends on its own chance of being sampled (Amplification by subsampling). So run the accountant at the oversampled group’s rate. In the running example, the minority is sampled four times as often and its records are held at \(\varepsilon = 4\), which raises the noise multiplier from 1.36 to 4.71. With it, the gap between the groups’ accuracies narrows from 9.93 points to 3.99. But it narrows by levelling down, since the majority loses 8.01 points. Research methods that clip or penalize each group separately need lawful group labels and private per-group statistics.

Some of the cost cannot be avoided by any algorithm. Learning a small group’s own rule means estimating it privately from that group’s few records, and private estimation from few records has an error floor that no mechanism beats (Lower bounds).

51.6 Cheat sheet

Rules of thumb

  • Report accuracy and privacy cost per group, with intervals, next to the non-private model’s.
  • Never report the gap alone, because levelling down closes it too.
